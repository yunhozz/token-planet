# 상점 시스템 개편 설계

작성일: 2026-10-01  
상태: 상세 설계 승인 완료 / 구현 진행 중

범위: 데스크톱 UI, Rust 도메인·SQLite, Supabase RPC·저장·공유 계약

## 1. 목표와 승인 범위

상점 가격과 상품 다양성을 높이고, 반복 구매한 풍경 오브젝트를 직접 배치하며 유용한 효과를 조합한다. 아바타 꾸미기 상품도 함께 판매한다.

사용자가 승인한 방향:

- 풍경과 아바타 상품을 별도 카테고리로 판매한다.
- 풍경 상품은 종류당 총 5개까지 보유하고 각 개체에 작은 색·형태 차이를 준다. 메인 풍경에서 드래그하여 배치한다.
- 풍경 효과는 토큰 적립, 문명 성장, 상점 할인, 초기화 대기 단축, 자연 오브젝트 제거 할인, 시대 달성 보상, 연속 활동 보상의 7종이다. 자연 오브젝트 생성 증가 효과는 포함하지 않는다.
- 상점 할인은 풍경과 아바타 상품 모두에 적용한다.
- 자연 오브젝트를 정해진 토큰 비용으로 제거할 수 있다.
- 출시 전 기존 보유 데이터 초기화가 가능하다. 이전 상품·보유 정보의 호환 이전을 요구하지 않는다.
- 아바타 가격대는 1억~5억 토큰이며 풍경 상품보다 대체로 높게 설정한다.

풍경 32종, 아바타 16종, 풍경 가격 500만~1억 토큰, 아바타 4개 착용 부위와 아래 개별 SKU·수치·합산 상한·지급 조건·동기화 규칙은 사용자의 수정된 상세 설계 문서 승인과 최종 승인으로 확정됐다. 본문의 상세값을 승인된 구현 기준으로 사용한다.

성공 조건: 반복 구매·개별 배치·효과 적용과 아바타 착용이 게스트와 로그인 계정에서 일관되고, 재실행·재시도·다른 기기 갱신으로 결제나 보상이 중복되지 않는다.

## 3. 출시 상품 구성과 경제

### 3.1 풍경 상품 32종

상품 표의 행마다 네 상품이며, 문명 성장 효과는 두 행에 걸쳐 8종이고 나머지 6개 효과는 각각 4종이다. 총 8 + 6×4 = 32종을 유지한다. 각 열의 기본 가격은 각각 500만 / 1,500만 / 4,000만 / 1억 토큰이다. 각 상품은 해당 행의 효과 하나를 가진다. 새 식별자를 사용하고 구형 SKU의 가격을 덮어쓰지 않는다.

| 효과 | 500만 | 1,500만 | 4,000만 | 1억 |
| --- | --- | --- | --- | --- |
| 토큰 적립 | 연못 `land_pond` | 우물 `land_well` | 온실 `land_greenhouse` | 저수지 `land_reservoir` |
| 문명 성장 | 수정탑 `land_crystal` | 학교 `land_school` | 천문대 `land_observatory` | 연구소 `land_laboratory` |
| 상점 할인 | 시장 `land_market` | 교역소 `land_trading_post` | 화물 터미널 `land_freight` | 대형 상가 `land_bazaar` |
| 초기화 대기 단축 | 탐사 로버 `land_rover` | 시계탑 `land_clocktower` | 발사대 `land_launchpad` | 포털 `land_portal` |
| 제거 할인 | 정리 도구함 `land_toolbox` | 굴착기 `land_excavator` | 암석 절단기 `land_cutter` | 재활용 로봇 `land_recycler` |
| 시대 달성 보상 | 깃발 `land_flag` | 얇은 고리 `land_thin_ring` | 이중 고리 `land_double_ring` | 작은 위성들 `land_moonlets` |
| 연속 활동 보상 | 등불 `land_lantern` | 별무리 `land_stars` | 오로라 `land_aurora` | 유성우 `land_meteors` |
| 문명 성장 (추가) | 꽃 정원 `land_garden` | 장식 나무 `land_tree` | 벤치 `land_bench` | 분수 `land_fountain` |

꽃 정원·장식 나무·벤치·분수는 문명 성장 효과로 재배정한다. 기본 가격과 개체당 성장 보너스는 같은 가격 열의 기존 문명 성장 상품과 동일하며, 문명 성장 합산 상한 +20%도 함께 적용한다.

각 SKU의 소유 한도는 5개다. 배치 중·보관 중을 모두 센다. 상품 재시도는 같은 구매 ID를 사용하며, 성공 후 추가 구매는 새 구매 ID를 만든다. 판매·환불·개체 삭제는 이번 범위에 넣지 않는다.

### 3.2 아바타 상품 16종

각 열의 가격은 1억 / 2억 / 3억 5,000만 / 5억 토큰이다. 전체 상품의 12종은 풍경 최고 기본가보다 높다.

| 부위 | 1억 | 2억 | 3억 5,000만 | 5억 |
| --- | --- | --- | --- | --- |
| 머리 | 탐험가 모자 `avatar_explorer_hat` | 왕관 `avatar_crown` | 우주 헬멧 `avatar_space_helmet` | 홀로그램 관 `avatar_halo` |
| 의상 | 작업복 `avatar_workwear` | 연구복 `avatar_labwear` | 우주복 `avatar_spacesuit` | 성운 의상 `avatar_nebula_suit` |
| 얼굴 | 안경 `avatar_glasses` | 선글라스 `avatar_sunglasses` | 고글 `avatar_goggles` | HUD 바이저 `avatar_hud` |
| 등 | 배낭 `avatar_backpack` | 망토 `avatar_cape` | 제트팩 `avatar_jetpack` | 에너지 날개 `avatar_wings` |

아바타 SKU는 한 번 구매하면 계속 보유한다. 부위당 하나를 착용하고 다른 부위는 함께 조합한다. 남성/여성 기본 모습 모두 지원한다. 머리·얼굴 레이어는 헬멧 등과 함께 착용해도 식별 가능하도록 제작한다.

아바타 상품에는 풍경 좌표·반복 구매·개체 변형·게임 효과를 부여하지 않는다. 미리보기, 착용, 해제를 제공하고 보유와 착용은 일반 행성 초기화 이후에도 유지한다.

### 3.3 가격 산정

확정 결제 가격은 `ceil(기본 가격 × (10000 - 할인 bps) / 10000)`이다. 상점 할인 최대치는 15%이며 결과 가격은 1토큰 이상이다. 정수 연산으로 계산한다. 상품, 카탈로그 수정 번호, 효과 수정 번호, 최종 가격을 담은 견적을 먼저 표시한다.

상점 할인은 결제 직전에 서버/게스트 로컬 트랜잭션이 확인한 활성 상태를 사용한다. 견적 이후 효과나 가격이 달라지면 재확인을 요청하고 자동으로 다른 가격에 결제하지 않는다. 새 구매가 제공할 할인은 그 구매 자체에는 적용하지 않는다.

## 4. 효과의 상세 규칙

배치된 풍경 개체만 활성화한다. 상점 미리보기·보관함·아바타 착용은 활성 효과가 아니다. 같은 효과는 합산하고 유형별 상한을 적용한다. 서로 다른 퍼센트 효과를 연쇄 곱하지 않는다.

| 효과 | 가격 열별 개체 효과 | 합산 상한/지급 조건 |
| --- | --- | --- |
| 토큰 적립 | +1 / 1.5 / 2 / 3% | +30%; 일반 초기화 시 기본 적립과 별도 게임 보너스 적립 |
| 문명 성장 | +1 / 1.5 / 2 / 3% | +20%; 활성 이후 발생한 활동의 성장 기여에만 적용 |
| 상점 할인 | −1 / 1.5 / 2 / 3% | −15%; 풍경·아바타 모두 적용 |
| 초기화 대기 | −1 / 1.5 / 2 / 3% | −25%; 다음 대기는 최소 18시간 |
| 자연 제거 할인 | −1 / 1.5 / 2 / 3% | −30% |
| 시대 달성 | 50만 / 150만 / 400만 / 1,000만 토큰 | 주기별 새 시대마다 한 번; 한 시대 총 1,000만 상한 |
| 연속 활동 | 1만 / 3만 / 8만 / 20만 토큰 | 연속 활동 둘째 날부터 하루 한 번; 일일 50만 상한 |

### 4.1 토큰과 성장 기여의 시점

실제 사용 토큰, 누적 사용량과 토큰 순위는 원본 집계다. 토큰 적립 보너스와 달성/활동 보상은 별도 게임 지갑 원장에 기록한다. 문명 순위는 보너스를 포함한 문명 성장 점수를 사용한다.

배치/회수 성공마다 활성 효과의 버전과 유효 시작 시각을 저장한다. 새 이벤트의 발생 시각에 해당하는 효과 구간을 사용한다. 설치 이전 기록과 활성 이전 기록에는 소급 적용하지 않는다. 활성 이후 이벤트가 늦게 수집되면 해당 발생 시각의 이력을 사용한다. 기기 시계가 아니라 로그인 계정은 서버 시각, 게스트는 로컬 기준 시각을 사용한다.

일별 실제 토큰 T와 해당 구간별 토큰 Ti, 성장 보너스 bi에 대해 기본 점수 C=`log2(1+T/100000)`, 추가 점수는 T>0이면 `C × sum(Ti×bi)/T`, T=0이면 0이다. bi는 비율이다. 이 계산은 이벤트 수집 순서에 의존하지 않는다. 자연 생성은 이 최종 성장 점수를 기존 생성 규칙에 입력한다. 별도의 자연 생성 증가 효과는 없다.

적립 보너스는 `sum(Ti × 적립비율i)`를 주기 전체에서 계산하고 마지막에 내림한다. 소수 부분은 해당 주기 안에서 누적하며 매 이벤트 내림으로 소액 사용을 손실시키지 않는다. 재수집·누적 스냅샷 대체·소스 비활성화에 의한 집계 수정은 적립 전 기여를 다시 계산한다. 동일 이벤트를 보너스 지급 이벤트로 반복 삽입하지 않는다.

### 4.2 보상과 대기 시간

- 시대 달성은 같은 주기에서 시대 1~4를 처음 통과할 때다. 여러 시대를 한 번에 통과하면 각각 한 번 처리한다. 통과 시점 활성 상품을 스냅샷으로 고정하고, 이후 배치해도 지나간 시대 보상을 받지 않는다. 점수가 줄었다가 다시 올라가도 지급 키를 재사용한다.
- 연속 활동은 계정의 최초 행성 시간대를 `reward_timezone`으로 고정해 날짜를 판단한다. 원본 토큰이 1개 이상인 날만 활동일이며 연속 둘째 날부터 대상이다. 달성 시점은 해당 날짜 첫 실제 활동의 발생 시각이다. 그 시점 효과를 사용하며 늦게 들어온 기록은 재판정하되 날짜별 지급을 한 번만 한다. 주기 변경으로 날짜별 보상을 다시 지급하지 않는다. 화면/행성 시간대를 바꿔도 보상 시간대는 바꾸지 않으며, 보상 패널에 기준 시간대를 표시한다.
- 토큰 적립·성장 계산은 원본 사용량 변화에 맞춰 재계산하고, 이미 확정 지급된 달성/활동 보상은 회수하지 않는다. 거짓 데이터나 외부 사용 기록 변조를 완전히 방지하는 보안 시스템은 별도 범위다.
- 일반 초기화 성공 시 그 순간의 대기 단축 비율을 저장하여 `다음 가능 시각 = 초기화 시각 + 24시간 × (1 - 비율)`로 확정한다. 배치를 보관함으로 돌리거나 다른 기기에서 갱신해도 확정 시각은 변하지 않는다. 최초 초기화 가능 여부는 기존 정책을 따른다.

## 5. 풍경 배치와 개체 외형

풍경 편집 모드에서 보관함 개체를 드래그하거나 배치한 개체를 다시 이동한다. 빈 공간 드래그는 카메라 이동, 오브젝트 드래그는 위치 이동으로 구분한다. 포인터 캡처와 화면→풍경 좌표 변환을 사용하여 확대/축소와 팬 중에도 정확히 배치한다.

지상 상품은 지상 안에, 하늘·고리 상품은 하늘 영역에 배치한다. 기존 네 슬롯의 한 개 제한은 없애고 상품의 `placement_zone`으로 범위를 검증한다. 하늘·고리도 개별 개체마다 이동 가능한 스프라이트로 만든다. 오브젝트 전체 경계가 해당 영역 안에 있어야 한다.

`land_stars`, `land_aurora`, `land_meteors`, `land_thin_ring`, `land_double_ring`, `land_moonlets`의 6종은 하늘 영역이며 나머지 26종은 지상 영역이다. 고리는 각 개체에 작은 행성 장식과 고리로 표현하여 여러 개를 독립 배치한다.

구매 개체는 기본 변형 번호 0~4 중 사용하지 않은 번호를 부여하고 추가 seed를 저장한다. 각 SKU는 5개의 구별 가능한 색조/형태 조합을 갖는다. 작은 크기·잎·지붕·장식 차이를 픽셀 아트로 표현하며 효과와 충돌 경계는 동일하다. 변형 버전도 저장해 재실행/동기화로 외형이 바뀌지 않게 한다. seed를 JS에서 다룰 때 정수 정밀도 손실을 피하도록 문자열 또는 안전한 크기로 전달한다.

배치 개체끼리 겹칠 수 있으나 바닥 기준 y와 안정적 개체 ID로 순서를 정해 선택/표시가 일관되게 한다. 아바타 통로를 막지 않도록 예약 통로에서는 배치하지 않는다. 장식 배치로 자동 아바타 경로를 다시 설계하지 않는다. 경계 밖 드롭·포인터 취소는 원래 위치로 복귀한다.

클릭 선택 후 배치 시작·방향키 이동·확정·취소·보관함 회수도 제공해 드래그만 강제하지 않는다. 저장 중인 개체에 새 이동을 중복 제출하지 않는다. 성공 후 새 버전 좌표를 확정하고, 실패하면 이전 좌표와 효과 상태로 복구한다.

## 6. 자연 오브젝트 제거

제거 기본 비용은 오브젝트의 **생성 시대**에 따라 고정한다. 현재 행성 시대나 개체 외형으로 바뀌지 않는다.

| 생성 시대 | 기본 제거 비용 |
| --- | ---: |
| 자연 | 100,000 |
| 농경 | 250,000 |
| 도시 | 500,000 |
| 산업 | 1,000,000 |
| 우주 | 2,000,000 |

편집 모드에서 자연 오브젝트를 선택하면 제거 기본가·현재 할인·최종가를 표시한다. 제거는 확인창에서 대상과 가격을 확인해야 한다. 풍경 구매 개체에는 자연 제거 결제를 적용하지 않는다.

제거 성공은 잔액 차감 원장과 `(account, cycle, stage, ordinal)` 제거 기록을 한 트랜잭션으로 저장한다. 제거 개체는 보관함에 들어가지 않으며 환불/복구는 제공하지 않는다. 원본 사용량과 성장 점수를 줄이지 않는다. 주기 내 생성된 ID 목록에는 제거 개체도 남겨 후속 성장 생성에서 이미 생성한 개체로 센다. 현재 주기에서 재생성하지 않고 다음 주기에는 새 ID의 자연 개체가 정상 생성된다.

## 8. 데이터 흐름, 원자성, 동기화

### 8.1 구매와 편집

1. UI가 최신 상태를 불러오고 상품 견적을 요청한다.
2. 최종 가격을 확인한 뒤 새 request ID와 견적을 제출한다.
3. 권한·카탈로그·견적·잔액·소유 한도를 트랜잭션 안에서 확인한다. 계정의 지갑 잠금과 개체 수 검증으로 두 기기의 동시 5번째 구매를 직렬화한다.
4. 차감·개체/아바타 소유 생성·결과 원장을 함께 확정하고 canonical state를 반환한다.
5. 배치/회수·착용·제거는 대상 버전과 cycle ID를 확인한다. 활성 구성이 바뀌면 효과 구간을 동시에 갱신한다.

### 8.2 게스트와 로그인

- 게스트는 SQLite가 권위 저장소이며 모든 게임 동작을 로컬 트랜잭션으로 실행한다.
- 로그인 계정의 구매/편집/초기화/보상 확정은 서버가 권위 저장소다. 오프라인에는 마지막 확정 상태와 수집 진행을 표시하되 비용·효과를 바꾸는 조작을 차단한다.
- 원본 수집은 오프라인에도 계속한다. 동기화 때 서버의 확정 효과 구간으로 일별 기여를 조정하고 재계산한다. 보너스와 지급 보상은 서버 확인 전에는 확정 잔액에 포함하지 않는다.
- 새 로그인 계정으로 게스트 정보를 가져오는 흐름은 유지한다. 가져오기 ID와 안정적인 구매/개체/보상 ID로 재시도를 처리하며 개체·배치·효과 이력·제거·원장·주기를 함께 검증한다. 서버가 fresh로 확인한 계정에만 전체 bootstrap을 허용한다. 의미 있는 profile·사용·원장·소유 상태가 있거나 기존 상태를 확정할 수 없는 active 계정에는 전체 가져오기를 보류하고 원본 게스트 상태를 보존한다. 한도/주기가 맞더라도 overwrite·부분 병합·부분 차감·부분 소유 복사를 하지 않는다. 로컬 지갑 금액은 주장값이며 원본 집계·주기·효과·결제 이력으로 검증할 수 없으면 전체 source_unverifiable 보류, 무적립 처리한다.

### 8.3 기여와 서버 계산

기존 기기별 실제 토큰 집계 계약을 유지하고, 같은 날짜 안의 효과 구간별 토큰 집계를 추가한다. 원본 대화/프롬프트를 업로드하지 않는다. 클라이언트가 임의 비율을 보내는 대신 서버에 저장된 효과 revision을 참조한다. 서버는 구간, 합계, 카탈로그 값과 주기를 검증하고 위의 성장·적립 공식을 같은 방식으로 계산한다.

구현 계약 보강: 인증된 개인 계정 전용 RPC `get_my_shop_effect_timeline()`은 account/cycle, 계정 전체에서 단조 증가하는 effect revision, 서버 기준 시각 및 효과 구간(revision·cycle·시작/종료 UTC·활성 개체 ID·확정 효과)을 반환한다. `auth.uid()`로 조회 대상을 고정하며 클라이언트 사용자 ID로 타인 이력을 선택하지 않는다. 초기 무효과 기준은 별도의 authoritative cycle_bounds로 전달하고 마감된 양수 효과 이력은 보존한다. 이 개인 이력을 WorldPlanet이나 공유 조회에 포함하지 않는다.

개인 DTO 필드는 `account_id`, `current_cycle_id`, `effect_revision`, `server_time_utc`, `reward_timezone`, `cycle_bounds`, `intervals`다. `cycle_bounds`의 각 항목은 서버가 기록한 `cycle_id`, `started_at_utc`, `ended_at_utc`이며 positive effect interval과 별도로 전달한다. 확정된 양수 구간을 먼저 매칭하고, 구간이 없을 때만 알려진 주기 경계 안에서 revision 0/기본 효과를 사용한다. 경계와 양수 이력이 모두 없는 과거 원본은 lifetime에 보존하며 기여/활동 보상 근거를 만들지 않는다. 서버가 기록하지 않은 과거 경계를 기기 시각이나 지갑 기록으로 추정하지 않는다. 각 구간은 `cycle_id`, `revision`, `started_at_utc`, `ended_at_utc`, `active_instance_ids`, `effects`를 사용한다. 동일 revision의 구간 내용은 불변이고 서버 시각만 전진할 수 있다. 새 revision은 이전 열린 구간의 종료를 확정할 수 있으나 닫힌 과거 구간의 효과를 다시 쓰지 않는다. 최초 서버 확정 보상 시간대는 로컬 placeholder를 교체하고 이후에는 계정별 고정값을 유지한다. 로그인 기기의 기여 재매핑은 서버 업로드 입력을 만들며, 한 기기의 성장 계산으로 서버 다기기 확정 성장값을 대체하지 않는다.

서버 이력 수신은 해당 계정의 로컬 구간과 확정 revision을 한 트랜잭션으로 교체한 뒤 기여를 재구축한다. 낮은 revision·같은 revision의 다른 내용·계정/주기 변경 후 도착한 응답은 반영하지 않으며, 검증 실패 시 기존 이력과 캐시는 유지한다. 새 구간 매핑으로 기여가 달라질 때만 canonical version을 올린다. 반복 조회·오프라인 수집·여러 기기·늦은 활동·초기화 전후·계정 전환을 독립 검사한다.

기기 내 이벤트 중복은 기존 usage key와 canonical 기여 수정 번호로 막는다. 기기 간 사용량은 기존 서버의 기기별 합산 정책을 따른다. 동일 원본 로그를 여러 기기에 복제한 경우까지 전역 중복 제거가 보장되는 구조는 현재 확인되지 않았으며 이번 작업에서 보장한다고 주장하지 않는다. 동일 기여 업로드·지급 요청의 재시도로 추가 보너스를 만드는 것은 반드시 막는다.

일반 초기화는 업로드된 현재 주기 기여를 기준으로 기본 토큰+적립 보너스를 한 번 확정한 후 새 주기를 연다. 로그인 상태에서 오프라인 초기화는 허용하지 않는다. 초기화 직전 해당 기기의 미전송 기여를 먼저 동기화한다. 다른 기기의 미전송 기록은 이미 마감된 주기의 게임 보상을 추가 지급하지 않고 원본 누적 사용 기록만 갱신한다. 서버의 기존 주기 검증과 대기 시간 검증도 새 frozen deadline 계약으로 변경한다.

### 8.4 자연 상태와 일반 초기화

서버 자연 생성의 전환은 계정/주기별 최초 개편 업로드에서 수행한다. 기존 클라이언트 영향이 있는 objects 배열과 표시 성장 점수를 생성 근거로 신뢰하지 않고, 검증된 서버 원본 일별 기여와 효과에서 재투영한 뒤 private marker를 같은 트랜잭션에 기록한다. 전환 실패는 원본·기여·개체·marker를 함께 롤백하며 재시도/새 계정/새 주기의 marker를 분리한다. 전체 world 자연 개체를 일괄 reset하지 않는다. 이후 서버가 확정한 정상 생성 ID/seed는 기여 감소와 여러 기기 갱신에도 보존한다. 기존 legacy의 과거 최대 생성 수는 검증 근거가 없으므로 해당 최초 전환에서 보존한다고 보장하지 않는다.

성장 갱신과 공유 장면은 tombstone을 우선 적용한다. 원격 objects 업로드나 오래된 캐시가 제거 상태를 덮어쓰지 않는다. 자연 생성은 전체 생성 ID를 기준으로 하고 표시만 제거 상태를 제외한다. 공유 행성은 구매 개체의 위치/변형과 아바타 착용, 자연 제거를 반영한다. 타인의 장면 편집은 허용하지 않는다.

일반 초기화는 자연 개체·제거 기록을 새 주기로 전환하고, 구매 풍경 개체의 배치를 보관함으로 돌린다. 구매 소유·지갑·아바타 착용은 유지한다. 연속 활동의 날짜별 지급 이력은 유지한다. 새 주기에 풍경 상품을 다시 배치해야 효과가 활성화된다.

## 9. 오류와 재시도 계약

동작 결과는 최소한 purchased/limit_reached/already_owned/insufficient_balance/quote_changed/catalog_mismatch/version_conflict/cycle_mismatch/not_owned/already_removed/request_conflict/unavailable을 구분한다.

같은 ID와 같은 payload는 이전 결과를 반환한다. 같은 ID를 다른 payload로 재사용하면 request_conflict다. 제거 대상이 이미 제거된 상태라면 추가 차감 없이 최신 상태를 반환한다. 실패한 배치/착용은 임시 UI를 복구하고 최신 상태를 불러온다. 네트워크 실패로 결과를 모를 때는 기존 요청 ID로 확인하며 새 요청으로 자동 구매하지 않는다.

견적 만료/효과 변경은 재견적 후 사용자 재확인을 요구한다. 오래된 주기나 stale 버전은 결제 전에 거절한다. 서버에 등록되지 않은 상품/변형·비정상 좌표·잘못된 소유자의 개체·범위를 벗어난 수치는 저장하지 않는다. 지출 합과 보상 합의 정수 overflow를 점검하고 음수 잔액을 허용하지 않는다.

## 10. UI와 아바타 표현

상점의 카테고리 탭은 풍경/아바타, 각 카테고리 내부는 상품/보관함이다. 풍경 카드는 효과, 기본가/할인가, 보유 n/5, 배치 수, 구매·미리보기를 표시한다. 아바타 카드는 부위, 가격, 보유/착용, 구매·미리보기·착용/해제를 표시한다.

미리보기는 현재 실제 배치·착용과 구별해 표시하고 상점 닫기/카테고리 변경/주기 변경에 해제한다. 메인 화면에는 편집 모드와 활성 효과 요약이 있다. 자연 선택 패널에는 제거 견적을, 구매 개체 선택 패널에는 효과와 회수를 표시한다.

AvatarSprite에 착용 데이터와 레이어를 추가하고 기본 모습, 좌우 전환, 걷기, 눈 깜빡임을 유지한다. 메인 풍경·팝오버·프로필 미리보기·공유 장면에서 같은 렌더러와 착용 계약을 사용한다. 장신구가 SVG 경계에서 잘리지 않도록 viewBox와 배치 경계를 조정한다. 동작 줄이기 설정과 키보드 조작을 유지한다.

## 11. 출시 전 데이터 정리

기존 마이그레이션 파일을 수정해 적용 이력을 바꾸지 않고 신규 전환 마이그레이션을 추가한다. 새 버전의 카탈로그·상점 스키마를 만들고 구형 장착/구매 계약을 종료한다. SQLite는 schema version에 따라 구형 상점 소유·장착·캐시·대기 요청을 초기화한다. 개발 서버의 구형 상점 데이터도 전환 시 정리한다.

초기화 승인 범위를 기존 상점/개발 게임 상태로 한정한다. 계정·인증·원본 사용 기록을 삭제하지 않는다. 지갑은 보존된 기본 적립 원장 기준으로 다시 계산하고 구형 구매 지출을 제거해 잔액과 원장 합이 일치하게 한다. 실제 환경 적용 위치와 대상은 구현/배포 단계에서 확인하며 이 문서 작성만으로 원격 DB를 실행하지 않는다.

## 12. 수용 기준과 검증 요구

1. 풍경 32종과 아바타 16종의 상품·가격·효과가 Rust/SQLite/서버/UI에서 일치한다. 아바타에도 확정 상점 할인이 적용된다.
2. 같은 풍경 SKU 5개까지 구매되고 6번째는 잔액 차감 없이 거절된다. 두 기기 동시 구매와 네트워크 재시도도 같은 한도를 지킨다.
3. 다섯 개체의 외형을 구분할 수 있고 재실행/동기화 후 동일하다. 각 개체의 위치·회수·효과가 독립적이다.
4. 줌/팬 상태의 드래그와 키보드 배치, 잘못된 드롭·취소·저장 실패를 확인한다. 미리보기는 실제 효과를 바꾸지 않는다.
5. 7종 효과의 합산/상한, 시점 전후 활동, 늦은 수집, 집계 수정, 날짜/주기 경계, 보상 중복을 확인한다. 실제 토큰 표시는 보너스로 증가하지 않는다.
6. 자연 제거의 생성 시대 가격·할인·확인·잔액 부족·재시도·동시 제거를 확인한다. 다음 성장 갱신과 원격 갱신에도 제거 개체가 되살아나지 않는다.
7. 자연 제거 기록이 다른 기기와 공유 장면에 반영되고, 새 주기는 이전 주기 제거 기록을 이어받지 않는지 확인한다.
8. 일반 초기화는 한 번 적립하고 대기 deadline을 고정한다. 풍경 소유는 유지하고 배치는 회수되며 아바타 착용은 유지된다.
9. 아바타 16상품의 남성/여성 조합, 착용/해제, 재실행, 공유 장면, 걷기/좌우 전환/잘림을 확인한다.
10. 게스트·로그인·오프라인·게스트 가져오기·계정 전환에서 소유/잔액/배치가 다른 계정에 섞이지 않는다.

행동 검증은 기존 frontend/Rust/SQL 체크를 해당 변경 범위에서 실행하고, 필요한 의미 있는 새 테스트는 Coder가 작성한다. 독립 QA와 상당한 데이터 계약 변경에 대한 Reviewer 검토를 거친다. 이 문서 작성 단계에서는 제품 코드·테스트·DB 적용을 수행하지 않는다.

## 13. 확정된 상세값과 실행 상태

표의 상품 구성·가격·개별 효과량·유형별 상한, 고정 제거 비용, 아바타 단일 소유, 달성/연속 활동 지급 조건, 초기화 시 대기 시간 확정 및 기여 마감 정책은 승인된 상세 설계다. 구현자는 본문에 명시된 값을 기준으로 구현하고 검증한다.

구매/효과/성장/자연 상태/서버 동기화의 공유 상태와 순서 의존성, UI·Rust·SQL의 서로 다른 검증 경로 때문에 별도 구현 계획을 작성했다. 상세 설계 승인 → read-only Planner 초안 → 팀장 통합·저장·자체 검토 → 사용자 계획 승인 단계는 완료됐으며, 승인된 계획에 따라 Coder 구현 → QA → Reviewer 검증을 진행한다. 이 문서는 상세 설계 기준이며 구현 계획은 별도 문서에 유지한다.

### 구현 중 전환 검증 메모 (2026-10-02)

개인 timeline cache의 기존 DB 재열기에는 account별 bounds 초기화 marker를 사용한다. 구형 캐시의 최초 서버 경계 수신만 허용하고 이후 과거 prepend를 거절하며, positive 이력·시각·revision·timezone 검증은 유지한다. 이 경로는 독립 QA 및 Reviewer를 통과했다. 서버 00208의 구형 미마감 과거 경계 전환도 c752630에서 독립 SQL43/523 및 Reviewer 검증을 통과했다. private RPC/cache 완료와 실제 client/worker·가져오기·공유 연결 완료는 구분한다.

### 개인 타임라인의 확정 high-water 계약

- effect_revision은 서버 계정 전체 high-water다. visible intervals의 마지막 revision 이상이어야 하며 빈 visible 목록도 허용한다. 정수 범위와 단조 증가를 검증한다.
- 닫힌 역사 행은 보존한다. 현재 주기가 아닌 NULL-ended bound/interval은 응답에서 제외하고 DB를 수정하거나 종료 시각을 추정하지 않는다. 유일한 open interval은 현재 주기의 마지막 interval이어야 한다.
- 이미 반환된 visible history는 immutable prefix다. 새 visible interval은 이전 글로벌 high-water보다 큰 revision, 이전 server_time 이상 시작 시각을 사용한다. 경계가 없는 미확인 과거 기록은 raw lifetime에만 남고, 알려진 closed positive interval은 해당 구간 자체를 권위로 먼저 매칭한다.
- 로그인 raw current 및 growth 날짜별 합계는 서버가 확인한 현재 cycle_bound와 같은 경계를 사용한다. 기존 activation 시각 원본 제외 규칙은 유지한다. guest/미초기화 signed fallback은 기존 로컬 cutoff를 사용하고, 권위 없는 과거 기록을 현재 revision 0으로 끌어오지 않는다.

구현 상태: 게스트 제거 UI 617e32c, 로그인 제거 native 843b8f0 및 UI 16ecb30은 독립 QA/Reviewer 완료다. 사용자 추가 명시 승인 후 canonical 집계/client/worker 연결을 진행하며, 로그인 초기화·완전 가져오기·공유·실제 화면 검증은 해당 후속 gate 전까지 미완료다. 검증은 mock/로컬 disposable DB로 한정하고 실제 사용자 집계를 hosted로 보내거나 hosted 거래/DB 적용을 실행하지 않는다.

### 2026-10-02 최종 로컬 기준점

로그인 초기화 결과의 단일 SQLite 원자 저장과 reset/timeline 시작 시각 경계 검증은 `4c1d18e`로 검증·커밋했다. 다만 authenticated worker 연결 패치는 자동 검토에서 거절돼 최종 코드에서 제거했으며, 현재 `sync_once`는 기존 동작 그대로다. 개인 timeline/client API와 로컬 cache/storage 완료를 실제 worker 연결 완료로 해석하지 않는다. 로그인 reset UI는 계속 비활성이다. 전체 guest import/public share 및 실제 화면 검증도 미완료다. 최종 독립 로컬 QA frontend315/Rust191(기존 HTTP3 제외)/TypeScript/Vite/checklib/diffcheck는 통과했지만 전체 기능 완료 판정은 아니다.
