# Token Planet 그룹 채팅 기능 명세

**상태:** 사용자 설계 및 written-spec 승인 완료 (2026-10-10). 구현 계획 승인이나 구현 완료를 의미하지 않는다.

## 1. 목적과 기존 제품과의 관계

비공개 그룹 구성원이 Token Planet 안에서 일반 텍스트 메시지를 주고받는다. 그룹마다 한 개의 채팅 공간을 제공하고, 현재 그룹 멤버십과 익명 Supabase 인증을 사용한다.

현재 멀티플레이 정책은 채팅을 후속 기능으로 분류한다. 이 명세는 승인된 그룹 채팅 설계를 제품 범위에 추가한다. 사용자가 작성한 채팅 본문은 사용량 수집기와 분리되며 Codex·Claude Code 원본 기록에서 읽거나 자동 생성하지 않는다.

기존 데이터 흐름은 유지한다. React는 좁은 Tauri API를 사용하고, Rust는 OS 보안 저장소에서 Supabase 세션을 읽어 서버와 통신한다. Auth 토큰은 React에 전달하지 않는다. 기존 sync_gate를 Realtime 연결 전체에 잡아 두지 않아 사용량 동기화·탈퇴·채팅 작업을 막지 않는다.

## 2. 승인된 요구와 기본값

### 사용자 승인 요구

- 목적은 그룹원끼리 일반 메시지를 교환하는 것이다.
- 첫 버전은 텍스트 전용이며 새 메시지는 거의 즉시 보여야 한다.
- Rust가 Supabase Realtime 연결을 관리한다.
- 각 메시지에 작성자의 프로필 아바타를 함께 표시한다.
- 멤버가 탈퇴해도 남은 멤버에게 그 멤버의 기존 메시지를 보인다.
- 작성자는 본인 메시지만 삭제할 수 있다. 삭제 후 본문은 지우고 “삭제된 메시지” 표시를 남긴다.
- 토큰 공유를 일시정지해도 채팅은 계속 사용할 수 있다.
- 새 멤버에게 가입 이전 메시지를 공개하지 않는다.
- 채팅 화면을 닫으면 운영체제 알림 대신 그룹 화면에 안 읽음 표시만 제공한다.

### 승인된 설계 기본값

- 본문은 최대 2,000 Unicode 코드 포인트로 제한한다. 서버가 최종 검증하며 화면과 Rust도 같은 기준을 적용한다.
- 기록은 최신 50개로 시작하고, 이전 기록은 커서로 추가 조회한다.
- 전송 실패 시 초안을 화면에 보존하고 자동 발송하지 않는다. 사용자가 다시 보내기를 선택한다.
- 연결 복구 시 연결 중 놓친 메시지와 삭제 상태를 서버 기록에서 다시 동기화한다.
- 그룹이 삭제되면 그 그룹의 채팅 데이터도 삭제한다.
- 메시지에는 작성 당시 표시명과 기존 내장 픽셀 아바타를 표시하고 그 값을 스냅샷으로 보존한다. 사용자 사진 업로드는 포함하지 않는다.
- 안 읽음 커서는 서버에 사용자·그룹별로 저장하되 다른 멤버에게 공개하지 않는다.
- 메시지 본문은 작성자의 삭제 또는 그룹 삭제까지 보관한다. tombstone은 본문을 지운다.
- 정상 연결에서 서버 저장 후 다른 온라인 멤버에게 보이는 목표는 P95 1초 이내다.

## 3. 범위와 사용자 흐름

그룹 탭의 그룹 화면에 채팅 진입점과 안 읽음 배지를 둔다. 각 메시지 옆에는 작성자 표시명과 프로필 아바타를 함께 보여준다. 기존 멤버 행성에서 사용하는 AvatarSprite와 같은 픽셀 아바타를 재사용한다. 현재 PlanetAvatar는 masculine/feminine 두 가지 내장 아바타 값이며, 업로드한 사진이나 이미지 첨부를 의미하지 않는다.

채팅 패널을 닫아도 그룹 탭이 보이는 동안 Rust 구독은 유지한다. 그룹 탭을 벗어나거나 앱이 종료되면 구독을 해제한다. 앱이 종료된 동안에는 푸시나 운영체제 알림을 보내지 않는다. 다음에 그룹 탭을 열면 서버에서 읽음 위치와 기록을 다시 확인해 배지를 복구한다.

채팅을 열면 참여 중인 그룹의 최신 기록을 조회하고, 더 오래된 기록은 커서 페이지네이션으로 추가한다. 순서는 서버가 부여한 그룹별 메시지 순번으로 결정한다. 메시지는 일반 텍스트로 렌더링하고 HTML이나 마크다운으로 실행하지 않는다.

메시지 전송에는 클라이언트 요청 ID를 함께 사용한다. 서버 응답과 Realtime 이벤트가 모두 도착해도 메시지 ID 기준으로 한 번만 표시한다. 네트워크 오류 때 초안을 지우지 않고 자동 재전송하지 않는다. 결과가 불분명한 요청의 사용자가 재시도할 경우 동일 요청 ID와 본문을 재사용해 중복 메시지를 막는다. 같은 ID에 다른 본문이 오면 서버가 거부한다.

본인 메시지 삭제는 본문을 비우고 삭제 시각을 기록하는 tombstone 변경이다. 화면은 “삭제된 메시지”를 표시하고 원래 본문을 다시 복구하지 않는다. 작성자·작성 시각·위치는 남겨 대화의 순서를 유지한다. 다른 작성자의 삭제 요청은 서버가 거부한다.

탈퇴가 완료되면 현재 화면의 해당 그룹 메시지·초안·읽음 상태를 지우고 구독을 종료한다. 지연된 이전 그룹의 응답과 이벤트도 버린다. 다른 멤버에게는 탈퇴한 사람의 기존 메시지가 남는다. 재가입 시에는 새 가입 경계 이후 메시지만 보인다.

## 4. 논리 데이터와 접근 경계

물리 테이블과 SQL 함수 이름은 구현 계획에서 확정하되, 데이터 계약은 다음을 충족한다.

| 데이터 | 계약 |
| --- | --- |
| 그룹 채팅 상태 | 그룹별 현재 메시지 순번을 서버에서 관리한다. |
| 메시지 | 그룹 ID, 그룹별 순번, 메시지 ID, 내부 작성자 ID, 작성 당시 표시명과 프로필 아바타 값, 본문, 서버 생성 시각, 삭제 상태·시각을 보관한다. |
| 가입 경계 | 그룹 멤버십에 그 멤버가 접근할 수 있는 첫 메시지 순번을 기록한다. 가입 시점에 현재 마지막 순번을 원자적으로 캡처한다. |
| 중복 방지 | 그룹·작성자·클라이언트 요청 ID 조합으로 전송을 중복 방지한다. 같은 요청 ID는 같은 본문에만 재사용할 수 있다. |
| 읽음 위치 | 사용자와 그룹별로 마지막으로 읽은 메시지 순번을 서버에 저장한다. 다른 멤버에게는 공개하지 않는다. |

새 메시지는 현재 순번보다 큰 서버 순번을 받는다. 메시지 저장과 멤버 가입 경계 캡처는 그룹별로 직렬화해, 가입과 동시에 발생한 전송도 과거 기록을 새 멤버에게 노출하지 않도록 한다. 메시지 기록 조회·이전 페이지·재연결 보충·안 읽음 집계·Realtime 전달 모두 같은 가입 경계를 적용한다.

현재 world_members.joined_at은 멤버십 시각으로 보존한다. 그러나 메시지 권한 경계는 단순 클라이언트 시각이나 타임스탬프 비교에 맡기지 않고, 서버가 가입 시 캡처하는 그룹별 순번으로 정의한다. 이 순번은 가입 이후 메시지만 보인다는 승인된 요구를 정확히 구현한다.

메시지 작성자 관계는 world_members 행 삭제에 cascade로 연결하지 않는다. 그렇지 않으면 탈퇴 시 기존 메시지가 삭제되기 때문이다. 그룹 삭제 시에는 그룹별 메시지·순번·읽음 위치·요청 중복 방지 데이터가 모두 함께 삭제된다. 기존 마지막 소유자 탈퇴가 그룹을 삭제하는 경로에도 같은 cascade 규칙이 적용된다.

모든 노출 테이블에 RLS와 명시적인 DB 권한을 적용한다. 멤버십은 그룹 ID와 인증된 auth.uid()로 서버에서 확인한다. 클라이언트가 전달한 작성자 ID·그룹 ID·가입 경계·작성 시각은 권한 근거로 사용하지 않는다. Auth 사용자는 자신의 현재 그룹에서 가입 경계 이후의 기록만 읽을 수 있다. 삽입·삭제는 권한 검사를 포함한 제한된 서버 RPC를 통해서만 수행한다. 직접 REST 접근, RPC, Realtime 중 어느 한 경로도 이 제한을 우회할 수 없다.

작성 당시 표시명과 기존 PlanetAvatar 값을 메시지에 스냅샷으로 저장해 멤버가 탈퇴하거나 나중에 프로필을 바꿔도 과거 메시지의 작성자 표현을 유지하는 방안을 제안한다. Auth 사용자 ID와 토큰은 그룹 공개 응답이나 화면 이벤트에 포함하지 않는다. 계정 영구 삭제 때 표시명·아바타와 기존 메시지 본문을 어떻게 처리할지는 아직 결정되지 않았다.

전송 RPC는 인증된 작성자 자신의 nickname과 avatar만 읽어 메시지에 기록한다. 사용량 공유가 일시정지되어 planet_member_state.shared_visible이 false여도 이 두 프로필 필드는 채팅 표시를 위해 사용할 수 있다. 이 경로는 토큰·행성 통계를 그룹에 다시 공개하지 않으며, 다른 멤버의 비공개 프로필 행을 읽지 않는다. 작성자 프로필이 아직 없으면 기존 그룹 화면의 기본 표시명과 기본 아바타를 사용한다.

## 5. React·Tauri·Rust·Supabase 경계

### React와 Tauri

React는 채팅 UI와 그룹 화면의 배지를 표시한다. Tauri 명령은 다음 기능을 제공한다.

- 현재 그룹 채팅 컨텍스트와 안 읽음 수 조회
- 최신 기록 및 커서 기반 이전 기록 조회
- 마지막으로 표시한 위치까지 읽음 처리
- 메시지 전송 및 본인 메시지 삭제
- Realtime 구독 시작·정지

명령 인자에 Auth 토큰을 넣지 않는다. React 이벤트는 그룹 컨텍스트, 세대 식별자, 메시지 ID와 현재 메시지 상태를 포함한다. 화면은 현재 그룹과 다른 이벤트를 버리고 메시지 ID 기준으로 중복을 제거한다.

### Rust

Rust는 기존 키링 세션으로 인증하고 Supabase Realtime WebSocket 연결, 세션 갱신, 구독, 재연결, 정리를 담당한다. 사용량 동기화의 60초 간격은 채팅 수신 지연에 적용하지 않는다. 기존 사용량 네트워크 작업의 잠금을 장시간 보유하지 않는다.

초기 연결 성공 후 기록과 읽음 위치를 동기화한다. 재연결 시 마지막 순번 뒤의 메시지 및 tombstone 변경을 모두 다시 가져온다. 구독 이벤트와 보충 조회 결과가 겹치면 메시지 순번과 메시지 ID로 합친다. 연결 실패 상태를 표시하고 지연 상한이 있는 재시도를 사용한다.

### Supabase Realtime·RPC

MVP의 실시간 변경은 Supabase Postgres Changes를 통해 메시지 INSERT 및 tombstone UPDATE로 전달한다. 현재 그룹 정원은 최대 10명이므로, 작은 그룹에서 RLS와 테이블 변경을 직접 이용하는 단순한 연결을 선택한다. 기록 조회·전송·삭제·읽음 위치는 인증된 사용자의 멤버십을 검사하는 서버 RPC로 처리한다. RLS 정책은 기록 조회와 Realtime 변경에 같은 가입 경계를 적용한다.

메시지 삭제는 DB 행의 hard DELETE가 아니라 본문을 지우는 UPDATE다. Supabase 문서상 Postgres Changes의 DELETE 이벤트는 RLS로 필터링되지 않으므로 hard DELETE를 사용하지 않는다. Realtime 스키마에는 사용자 정의 테이블·함수를 추가하지 않는다. 구현 시 현행 Supabase Realtime 설정, 인증 갱신과 Rust WebSocket 의존성을 확인한다.

## 6. 읽음 표시와 오류 처리

읽음 위치는 사용자 본인의 비공개 그룹 커서로 서버에 보관한다. 상대방에게 개별 읽음 여부나 읽은 사람 목록을 보여주지 않는다. 채팅이 보이고 최신 메시지 위치에 도달했을 때만 그 지점까지 읽음 처리한다. 이전 기록을 읽는 동안 새 메시지가 오면 자동으로 아래로 이동시키지 않고 새 메시지 표시를 유지한다.

안 읽음 수는 현재 가입 경계 이후 접근할 수 있고, 개인 읽음 순번보다 뒤에 있으며, tombstone이 아닌 다른 작성자의 메시지를 기준으로 계산한다. 숨겨진 채팅 중에는 그룹 화면의 채팅 진입점에만 배지를 표시한다. 서버 커서를 사용하므로 다음 앱 실행 때도 그룹 화면에서 읽지 않은 메시지를 복구할 수 있다.

네트워크가 끊기면 기존 기록과 전송 초안을 유지한다. 재연결·앱 재활성화 때 현재 그룹과 멤버십을 다시 확인하고 누락된 INSERT 및 삭제 상태를 동기화한다. 인증 만료, 멤버 탈퇴, 그룹 삭제 시 구독과 해당 그룹 UI 상태를 종료한다. 이전 컨텍스트에서 도착한 이벤트가 새 그룹의 내용을 덮어쓰면 안 된다.

정량적인 “거의 즉시” 기준으로, 정상 연결 상태에서 서버 저장 이후 다른 온라인 멤버 화면에 보이는 시간이 **P95 1초 이내**인 목표를 제안한다. 네트워크 단절 시간은 이 지표에서 제외하고 별도 재연결 복구 기준으로 본다. 이 수치는 사용자 승인 전에 검토할 제안이다.

## 7. 개인정보·보존

채팅 본문은 사용자가 직접 작성해 서버에 저장하는 그룹 데이터다. 원본 로그·프롬프트·도구 출력·파일 경로·Auth 토큰·지갑 비공개 데이터는 가져오거나 이벤트·오류 로그에 기록하지 않는다. 채팅 본문을 사용량 원장·사용량 대기열·행성 데이터에 복사하지 않는다. 클라이언트는 본문을 일반 텍스트로 표시한다. 메시지 옆 아바타는 기존 내장 PlanetAvatar 값만 사용하며 사용자 이미지 업로드나 이미지 첨부 기능을 추가하지 않는다.

공유 일시정지는 사용량 업로드 동작만 멈추며 채팅을 막지 않는다. 그룹 탈퇴는 권한과 화면 상태를 정리하지만 작성한 기존 메시지는 삭제하지 않는다. 본인 메시지 삭제는 해당 본문의 운영 DB 값을 지우고 tombstone을 남긴다.

별도 만료 정책이 정해지지 않았으므로, 그룹 삭제 또는 작성자의 본인 삭제까지 메시지를 보관하는 것을 제안한다. tombstone은 활성 DB와 클라이언트 캐시에서 본문을 제거한다. 서비스 백업의 만료 주기·영구 Auth 계정 삭제 시 처리·멤버 탈퇴 후 표시명 유지 범위는 미확정이며, 구현 전 제품 정책으로 결정해야 한다.

## 8. 수용 기준과 검증 조건

1. 같은 그룹의 서로 다른 두 인증 사용자가 텍스트 메시지를 실시간으로 보내고 받고, 앱 재실행 후에도 허용된 기록을 조회한다.
2. 정상 연결 기준 P95 1초 이내 수신 목표를 검증한다. 이 정량 목표는 명세 승인 때 확인한다.
3. 가입 전 메시지는 최초 조회, 이전 페이지, 재연결 보충, 안 읽음 집계, Realtime에서 접근할 수 없다.
4. 비멤버·다른 그룹 사용자·탈퇴 멤버의 직접 REST, RPC, Realtime 접근을 모두 거부한다.
5. 작성자·그룹·가입 경계·작성 시각을 위조한 전송과 본인이 아닌 메시지 삭제를 거부한다.
6. 응답 유실 후 동일 요청 ID를 재시도해도 한 메시지만 저장·표시하고, 본문을 바꾼 요청 ID 재사용은 거부한다.
7. 단절 중 메시지 생성과 tombstone 변경을 모두 재연결 후 복구하며 삭제 본문이 다시 나타나지 않는다.
8. 숨겨진 채팅은 그룹 화면에만 안 읽음 표시를 보인다. 채팅에서 최신 메시지까지 확인하면 안 읽음 수가 줄고, 다른 멤버에게 읽음 정보는 노출되지 않는다.
9. 본인 메시지 삭제 시 본문이 제거되고 “삭제된 메시지” 표시가 남는다. 반복 삭제는 멱등적이고, 그룹에 남은 멤버는 작성자가 탈퇴한 뒤에도 메시지를 본다.
10. 새 멤버와 재가입 멤버는 각 가입 경계 이후 메시지만 볼 수 있고, 탈퇴 직후 기존 그룹 구독·초안·화면 상태가 정리된다.
11. 토큰 공유 일시정지와 공유 집계 삭제가 채팅 읽기·전송을 막지 않는다. 일시정지된 작성자도 프로필 아바타와 표시명을 메시지에 표시할 수 있고, 토큰·행성 통계는 다시 공개되지 않는다.
12. 그룹 삭제 경로에서 그룹의 메시지·읽음·중복 방지 데이터가 모두 삭제된다.
13. HTML 본문이 실행되지 않고 빈 본문·공백만 있는 본문·2,000자 초과 본문을 서버가 거부한다.
14. 각 메시지에 작성 당시 표시명과 기존 픽셀 프로필 아바타가 함께 표시되고, 접근성 이름에 작성자 정보가 제공된다.
15. 로컬 Supabase 개발 안내에 Realtime 서비스가 포함되고, 두 독립 인증 사용자로 접근 경계를 검증한다.

화면 버튼의 비활성화만으로 권한 검증을 통과 처리하지 않는다. 테스트는 DB·API·Realtime 경로를 별도의 인증 컨텍스트로 확인한다. 운영 데이터나 production 대상 검증은 이 기능의 수용 기준에 포함하지 않는다.

## 9. 구현 전 확인할 운영 정책

영구 Auth 계정 삭제는 이번 기능에서 새로 제공하지 않는다. 만약 기존 서비스의 계정 삭제 경로가 채팅 메시지에 영향을 준다면, 작성자 스냅샷과 본문 보존 방식을 구현 전에 확인하고 이 명세를 갱신한다.

메시지 삭제는 활성 데이터베이스와 앱 캐시에서 본문을 제거하지만, 서비스 백업에서 즉시 삭제됨을 보장하지 않는다. 기존 Supabase 프로젝트의 백업·로그 보존 정책을 확인하고 구현·운영 문서에서 tombstone의 보장 범위를 명확히 한다.
