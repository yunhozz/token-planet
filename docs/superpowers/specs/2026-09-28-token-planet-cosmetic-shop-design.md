# Token Planet 행성 꾸미기 상점 설계

**작성일:** 2026-09-28  
**상태:** 사용자 검토 대기 · 커밋하지 않음

## 목표와 성공 기준

행성을 초기화해 적립한 토큰으로 외형 장식을 구매하고, 보유한 장식을 새 행성에도 다시 장착할 수 있게 한다. 장식은 성장 크레딧, 오브젝트 생성, 사용량 집계, 순위에 영향을 주지 않는다.

1. 계정 없이 쓰는 개인 행성에서도 장식을 구매하고 장착할 수 있다.
2. 로그인 계정의 구매는 온라인에서 잔액을 확인하고 한 번만 차감한다. 재시도나 다른 기기의 동일 상품 구매로 중복 차감되지 않는다.
3. 구매한 장식은 영구 보유한다. 행성을 초기화하면 장착만 해제되고 새 행성에서 다시 장착할 수 있다.
4. 그룹 멤버에게는 장착된 외형만 보인다. 잔액, 구매 내역, 보유 목록은 본인만 볼 수 있다.
5. 계정 전환, 앱 재시작, 동기화 재시도 후에도 구매와 장착 상태가 다른 계정에 섞이거나 사라지지 않는다.

## 제품 범위

상점은 기존 상세 화면의 내 행성 영역에서 열고, 같은 화면에서 보관함을 전환해 본다. 구매 전에는 현재 행성에 장식을 적용한 미리보기를 보여준다. 구매 버튼에는 가격과 구매 후 잔액을 표시하고 확인을 받는다. 구매와 장착은 별개 동작이다. 이미 보유한 상품은 다시 구매할 수 없고, 각 슬롯에는 장식 하나만 장착할 수 있다. 장착 해제는 무료다.

첫 출시 카탈로그는 아래 세 슬롯과 여섯 상품으로 시작한다. 이 개수와 슬롯당 상품 수는 데이터 모델이나 화면의 고정 제한이 아니다. 모든 상품은 영구 보유이며 재구매하지 않는다. 가격 단위는 현재 지갑에 적립되는 토큰과 같다.

| 슬롯 | 기본형 · 100,000 토큰 | 고급형 · 500,000 토큰 |
| --- | --- | --- |
| 하늘 | 별무리 | 오로라 |
| 고리 | 얇은 고리 | 이중 고리 |
| 지표 | 깃발 | 수정탑 |

각 슬롯에는 변하지 않는 `slot_id`를, 각 상품에는 변하지 않는 SKU와 소속 `slot_id`, 가격, 외형 정의를 둔다. 후속 버전에서 가격을 바꿔야 한다면 기존 SKU의 가격을 수정하지 않고 새 SKU를 만든다. 표시명이나 기본형·고급형 구분은 구매 키가 아니다. 장식은 모든 시대에서 보이되, 기존 성장 오브젝트와 겹치지 않는 영역에 그린다. 첫 버전에는 자유 배치 편집기를 넣지 않는다.

### 향후 슬롯·상품 추가 규칙

- 카탈로그는 슬롯 목록과 상품 목록으로 표현한다. 상점·보관함은 슬롯 및 해당 상품을 목록으로 렌더링하며 `3개 슬롯`, `슬롯당 2개`, `두 가격 단계`를 코드나 API의 고정 필드로 만들지 않는다.
- 구매 원장은 SKU를 참조하고, 장착 원장은 `(계정, 행성 주기, slot_id) → SKU`를 저장한다. 서버는 SKU가 해당 슬롯에 속하는지 확인한다. 새 상품이나 새 슬롯을 추가해도 기존 구매·장착 테이블과 RPC의 형태는 바꾸지 않는다.
- 상품 추가는 서버 카탈로그에 SKU·가격·소속 슬롯을 등록하고, 앱에 표시 정보와 장식 그림을 추가하는 릴리스로 진행한다. 새 슬롯은 여기에 슬롯 표시 정보와 행성 장면의 배치·그리기 규칙을 추가한다. 원격 이미지나 관리자용 상품 편집 기능은 이번 범위에 넣지 않는다.
- 서버 카탈로그를 먼저 배포한다. 구버전 앱이 모르는 슬롯이나 SKU를 받아도 보유·장착 상태를 삭제하거나 다른 상품으로 바꾸지 않는다. 구버전 앱은 해당 장식을 그리지 않고 구매 선택지에도 표시하지 않는다. 새 앱은 자신이 그릴 수 있는 SKU만 구매·장착할 수 있다.
- 판매를 중단한 상품은 새 구매 목록에서 숨길 수 있지만 기존 구매 기록과 소유권은 유지한다. 보유자가 계속 장착할 수 있도록 앱의 그림 정의도 유지한다.

## 잔액과 구매 규칙

현재 지갑 적립 원장은 행성 초기화마다 `previous_cycle_id`를 키로 한 번 적립한다. 상점은 이를 수정하지 않고 별도 구매 원장을 추가한다.

```text
사용 가능 잔액 = 확정된 초기화 적립 합계 − 확정된 구매 가격 합계
```

구매 원장에는 구매 ID(UUID), SKU, 구매 당시 확정 가격, 구매 시각, 계정 범위를 기록한다. 구매 ID는 네트워크 재시도에도 유지한다. 동일 계정·동일 구매 ID의 재시도는 원래 결과를 돌려주고, 동일 계정·동일 SKU는 한 번만 보유할 수 있다. 가격은 클라이언트가 임의로 보내 확정하지 않는다. 서버는 등록된 SKU의 가격을 사용한다. 잔액 부족, 이미 보유, 상품 버전 불일치는 서로 다른 결과로 표시한다.

비로그인 개인 행성은 SQLite 거래 안에서 잔액 확인과 구매 기록 삽입을 함께 처리한다. 로그인한 계정은 Supabase 구매 RPC가 계정별 잠금 행을 잡은 뒤 잔액 확인과 구매 삽입을 한 거래에서 처리한다. 아직 행성 상태를 업로드하지 않은 계정에도 잠금 행을 만들 수 있다. 서버 성공 응답을 받은 뒤 로컬 보관함과 잔액을 갱신한다. 네트워크 결과를 받지 못한 경우 동일 구매 ID로 재조회 또는 재시도하며, 로컬에서 성공을 추정해 차감하지 않는다. 로그인 중 오프라인이거나 동기화가 일시정지된 상태에서는 보관함과 미리보기는 열리지만 구매와 장착 변경은 확정할 수 없다.

현재 서비스는 클라이언트가 보고한 사용량과 초기화 적립을 받아들인다. 상점도 이 신뢰 경계를 유지하며, 수정된 클라이언트의 허위 적립을 방지하는 경제 시스템으로 설명하지 않는다.

## 보유와 장착 상태

구매 내역은 계정에 속하고 행성 주기와 무관하다. 장착 상태는 `slot_id → SKU`와 현재 `cycle_id`에 속한다. 같은 슬롯의 다른 보유 상품을 장착하면 기존 상품은 보관함에 남고 장착만 바뀐다. 행성 초기화 거래는 존재하는 모든 슬롯의 장착 상태를 비운다. 다른 기기의 오래된 주기에서 온 장착 요청은 서버가 거절하므로 초기화된 행성에 장식이 되살아나지 않는다.

비로그인 장착 변경은 로컬에 즉시 저장한다. 로그인 계정의 장착 변경은 현재 슬롯 버전을 함께 보내 온라인 RPC로 확정하고, 성공한 서버 상태를 로컬에 반영한다. 다른 기기가 먼저 바꿨다면 오래된 버전의 요청을 거절하고 새 장착 상태를 보여준다. 연결이 끊기면 마지막으로 확정된 장착 모습을 계속 보여준다. 구매·장착 상태는 기존 행성 프로필과 마찬가지로 계정별 로컬 저장 공간을 사용한다.

## 첫 로그인과 계정 전환

첫 로그인 때 계정 없이 사용하던 행성을 채택하는 현재 흐름에 맞춰, 계정 전환 전에 게스트 적립·구매 내역을 별도로 보존하고 함께 제출한다. 서버는 SKU와 구매 가격을 확인하고, 이미 있는 적립·구매 키를 중복 반영하지 않으며, 모든 새 구매를 반영해도 잔액이 음수가 되지 않을 때만 가져오기를 한 거래에서 확정한다. 대상 계정이 이미 같은 SKU를 보유했다면 추가 차감 없이 기존 보유 상태를 사용한다.

검증에 실패하면 로그인 자체는 유지한다. 로컬 구매 내역은 계정과 분리된 보관 상태로 남기고, 가져오지 못한 이유를 사용자에게 알린다. 서버에 확정되지 않은 구매를 계정의 보유 상품으로 표시하지 않는다. 다른 계정으로 전환할 때도 각 계정의 구매와 장착 상태를 별도로 저장하고 복원한다. 이전 계정의 구매를 새 계정으로 자동 전송하지 않는다.

## 데이터와 인터페이스 경계

- **Rust·SQLite:** 앱이 그릴 수 있는 카탈로그 정의와 로컬 구매 원장, 계정별 장착 상태, 잔액 계산, 비로그인 구매 거래를 담당한다. React에는 좁은 `get_shop_state`, `purchase_cosmetic`, `equip_cosmetic` 명령으로 필요한 결과만 제공한다. 슬롯·상품 ID는 문자열 키로 저장하고 카탈로그에 있는 값인지 검증한다.
- **Supabase:** 슬롯·상품 카탈로그, 비공개 구매 원장, 계정별 구매 잠금 행, 장착 상태를 추가한다. 구매·장착 RPC는 `auth.uid()`로 계정을 제한하고 SKU·슬롯 소속, 구매 중복, 잔액, 현재 주기, 보유 여부를 검사한다. 기존 적립 원장은 유지하고 반환 잔액만 적립 합계에서 구매 합계를 뺀 값으로 바꾼다. 기존 행성 상태 업로드가 새 주기를 확정할 때는 같은 거래에서 모든 슬롯의 장착 상태를 해제한다. 로그인 후 로컬 구매 가져오기도 서버 거래로 검증한다.
- **React:** 카탈로그의 슬롯·상품 목록을 순회해 상점·보관함, 잔액과 가격, 미리보기, 장착 상태, 구매 결과를 표시한다. 장면 렌더러는 지원하는 `slot_id`와 SKU별 그림을 등록한다. 상품 가격과 잔액의 최종 판정은 Rust 또는 서버 응답을 따른다.
- **그룹 조회:** 기존 멤버별 행성 조회 결과에 현재 주기의 장착 항목 목록(`slot_id`, SKU)만 추가한다. 구매 ID, 가격, 적립·차감 원장, 잔액은 반환하지 않는다. 공유가 중지되어 그룹에서 행성이 숨겨진 경우 장식도 표시되지 않는다.

원본 사용 기록, 프롬프트, 응답 내용과 로컬 파일 경로는 기존처럼 기기에 남는다. 상점은 이 데이터를 읽거나 전송하지 않는다.

## 오류와 복구

- 잔액이 부족하면 구매를 기록하지 않고 필요한 금액과 현재 사용 가능 잔액을 표시한다.
- 이미 보유한 상품을 다른 기기에서 동시에 사려 했다면 추가 차감 없이 보유 상태를 새로고침한다.
- 서버 응답이 유실되면 같은 구매 ID로 결과를 확인해 성공 여부를 결정한다.
- 앱을 재시작하거나 계정을 전환해도 미확정 구매를 성공으로 표시하지 않는다.
- 첫 로그인 가져오기가 실패하면 로컬 내역을 보존하고 계정 상태와 섞지 않는다.
- 서버의 현재 행성 주기와 다른 장착 요청은 거절하고 최신 행성 상태를 다시 불러온다.

## 검증 기준

1. 적립 100,000 토큰으로 기본형 하나를 산 뒤 잔액이 0이며, 같은 구매 ID나 SKU를 재전송해도 추가 차감이 없다.
2. 500,000 토큰 미만에서 고급형 구매가 거절되고 적립·구매 원장이 그대로 남는다.
3. 두 기기에서 동시에 구매할 때 서버 잔액이 음수가 되지 않고 보유 상품이 중복되지 않는다.
4. 비로그인 구매가 앱 재시작 후 남고, 첫 로그인 때 적립과 함께 한 번만 계정으로 옮겨진다. 가져오기 실패 시 로컬 내역이 보존된다.
5. 초기화 후 장착은 해제되지만 구매 내역은 남는다. 이전 주기의 지연된 장착 요청으로 새 행성에 장식이 복원되지 않는다.
6. 계정 전환 시 각 계정의 보유·장착 상태가 분리되고, 그룹 응답에는 장착 SKU만 포함된다.
7. macOS와 Windows의 실제 앱에서 상점 미리보기, 구매, 장착, 재시작, 로그인 후 동기화, 네트워크 실패·재시도를 확인한다.
8. 기존 슬롯에 세 번째 상품과 새로운 네 번째 슬롯을 테스트 카탈로그로 추가해도 구매·장착 테이블, RPC 형태, 상점 목록 화면을 변경하지 않고 동작한다. 새 슬롯은 장면 그림과 배치 규칙을 추가해 표시한다.

## 출시 순서와 제외 범위

1. 로컬 원장·장착 상태와 카탈로그를 구현해 계정 없는 개인 행성에서 검증한다.
2. Supabase 구매·장착 RPC와 첫 로그인 가져오기를 구현하고 동시 구매 및 계정 격리를 검증한다.
3. 상세 화면, 미리보기, 그룹의 장착 외형을 연결하고 실제 두 기기에서 확인한다.

공유 기능의 기존 호스팅 OTP, 마이그레이션, macOS·Windows 실기 검증은 상점의 계정 동기화 출시에도 필요한 선행 조건이다. 실물 결제, 성장 효과, 상품 관리 화면, 자유 배치, 선물·거래, 구매 취소와 환불은 이번 범위에서 제외한다.
