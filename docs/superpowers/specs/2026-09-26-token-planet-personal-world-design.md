# Token Planet 개인 행성 성장 설계

**작성일:** 2026-09-26
**상태:** 사용자 검토 대기

## 목표

Token Planet을 각 사용자가 자신의 토큰 사용량으로 개인 행성을 키우고, 초대 그룹에서 서로의 행성과 성장 기록을 비교하는 데스크톱 앱으로 개편한다. 행성은 자연 생태계에서 시작해 문명과 우주 문명으로 발전한다. 픽셀 아트 UI와 둥근 가장자리가 보이는 작은 행성 디오라마로 변화를 보여준다.

성공 기준은 다음과 같다.

1. 새 사용자가 남성 또는 여성 픽셀 아바타를 선택하고 닉네임을 정할 수 있다.
2. 개편 이후 사용량만 행성 성장과 점수판에 반영되고, 같은 사용 기록이 오브젝트를 중복 생성하지 않는다.
3. 자연, 정착지, 도시, 산업, 우주 문명의 오브젝트가 순서대로 생기며 시대가 발전할수록 새 오브젝트가 느리게 생성된다.
4. 어느 시대에서든 초기화할 수 있다. 초기화 시 현재 행성의 토큰 수가 지갑에 한 번 적립되고, 다음 행성은 자연 생태계부터 시작한다.
5. 공유 그룹에는 멤버별 독립 행성이 표시되고, 토큰 사용량과 문명 발전 점수의 순위표를 각각 제공한다.
6. 원본 사용 기록, 프롬프트, 응답 내용과 파일 경로는 사용자 기기에 남는다.

## 제품 방향

- 개인 행성이 기본 경험이고, 공유 그룹은 행성과 순위표를 비교하는 선택형 기능이다.
- 그룹의 각 사용자는 자신의 행성만 성장시킨다. 토큰을 그룹 행성 하나에 합산하지 않는다.
- 앱 표기명은 `Token Planet`으로 통일한다.
- 유지 대상: Tauri 2, React, Rust 데스크톱 앱, macOS 메뉴 바 및 Windows 트레이 진입점, Codex와 Claude Code 수집, 선택형 계정 및 초대 그룹.

## 주요 화면

### 첫 실행

사용자는 픽셀 아트 남성 또는 여성 캐릭터를 고른다. 선택은 외형에만 영향을 주며 능력이나 성장 속도 차이는 없다. 그룹을 만들거나 참여할 때 비교 화면에 쓸 닉네임을 정한다. 이메일 주소는 다른 참여자에게 공개하지 않는다.

### 내 행성 대시보드

- 둥근 행성 가장자리가 보이는 작은 픽셀 디오라마를 중심에 둔다.
- 제한된 색상 팔레트, 픽셀 아이콘과 서체 등 UI 전체에 픽셀 아트 스타일을 적용한다.
- 현재 시대, 다음 시대 진행도, 다음 오브젝트 생성까지의 진행도, 최근 생성 요소, 이번 행성의 토큰 수와 지갑 잔액을 보여준다.
- 남성/여성 아바타는 행성 표면에 거주자로 나타난다.
- 생성물이 많아지면 지형, 숲, 도시 구역을 픽셀 타일 묶음으로 표현해 겹침을 줄인다. 이전에 생성된 요소는 지우거나 교체하지 않는다.
- 사용자의 정확한 토큰 사용량과 Codex·Claude Code 수집 및 집계 상태를 표시한다. 원본 기록이 불완전하면 확인된 합계와 미확인 상태를 구분한다.

### 참여자 행성과 점수판

- 초대 그룹의 멤버 한 명당 독립 행성 하나를 보여준다. 행성 카드는 같은 크기로 표시하고, 선택 시 큰 디오라마로 볼 수 있다.
- 별도의 두 순위표를 제공한다: **누적 토큰 사용량**과 **현재 행성 문명 발전 점수**.
- 각 순위표에 순위와 정확한 값을 공개한다. 토큰 사용량 순위는 개편 후 누적된 총 사용량, 문명 발전 순위는 현재 행성의 성장 크레딧을 기준으로 한다.
- 초기화해도 누적 토큰 사용량 순위는 유지된다. 문명 발전 점수는 새 행성에서 0부터 다시 쌓는다.
- 행성의 닉네임, 아바타, 시대와 픽셀 모습은 갤러리에 표시한다. 다른 사람의 행성을 편집하거나 대신 성장시킬 수 없다.
- 기존 MVP의 초대 전용 그룹, 계정당 한 그룹, 최대 10명, 초대 만료·철회, 소유권 이전 및 탈퇴 정책을 유지한다.

## 행성 성장 규칙

### 시대와 최종 시대

시대는 순서대로 열린다. 이전 시대의 자연과 건물은 행성에 남고, 아직 열리지 않은 시대의 오브젝트는 생성하지 않는다.

| 단계 | 시대 | 생성 요소 예시 | 누적 성장 크레딧 |
| --- | --- | --- | ---: |
| 0 | 자연 생태계 | 바위, 물, 지형, 나무, 기초 생물 | 0부터 시작 |
| 1 | 정착·농경 | 야영지, 오두막, 경작지, 오솔길 | 5 |
| 2 | 마을·초기 도시 | 집, 작업장, 광장, 도로 | 20 |
| 3 | 산업 문명 | 공장, 전력 시설, 도시 구역 | 50 |
| 4 | 첨단·우주 문명 | 연구 시설, 첨단 건물, 발사 시설과 궤도 요소 | 100 |

첨단·우주 문명은 100 크레딧에서 열리는 최종 시대다. 그 이후에는 새 시대가 열리지 않지만, 문명 발전 점수와 오브젝트는 계속 쌓인다. 사용자는 어느 시대에서든 초기화할 수 있다.

### 성장 크레딧과 오브젝트 생성 속도

기존에 승인된 사용자별 일일 성장 규칙을 적용한다.

```text
사용자-일 성장 크레딧 = log2(1 + 해당 일의 확인된 토큰 / 100,000)
현재 행성 성장 크레딧 = 개편 이후 사용자-일 성장 크레딧의 합계
```

사용자-일 구간은 고정된 IANA 시간대를 따른다. 그룹 행성은 기존처럼 그룹 생성 시 정한 시간대를 사용하고, 개인 행성은 생성 시 정한 시간대를 사용한다. 초기화가 하루 중간에 일어나면 원장의 기록 시각을 경계로 초기화 이후 사용량만 새 행성의 토큰 수와 성장에 반영한다.

시대별 다음 오브젝트 하나를 생성하는 데 필요한 추가 성장 크레딧은 다음과 같이 늘어난다.

| 현재 시대 | 오브젝트 1개당 크레딧 |
| --- | ---: |
| 자연 생태계 | 1 |
| 정착·농경 | 2 |
| 마을·초기 도시 | 4 |
| 산업 문명 | 8 |
| 첨단·우주 문명 | 16 |

시대 진행에 필요한 크레딧 간격도 `5, 15, 30, 50, 100`으로 늘어나므로 문명 해금도 점차 느려진다. 오브젝트 생성은 새 사용 기록마다 한 개씩 만들지 않고 성장 크레딧 누적량으로 조절한다. 남은 분수 크레딧은 다음 오브젝트에 이월하며, 시대가 바뀐 뒤에는 새 시대의 생성 간격을 적용한다. 초기 지형은 빈 행성으로 보이지 않도록 기본 장면으로 제공한다.

각 생성 시 현재 시대에서 허용된 오브젝트 하나를 랜덤 선택한다. 랜덤 시드, 종류, 위치는 로컬 성장 원장에 보존해 앱 재시작, 파일 재검사, 동기화 재시도 후에도 결과가 바뀌거나 중복 생성되지 않게 한다.

### 초기화와 지갑

- 어느 시대에서든 초기화할 수 있다. 초기화 직후에는 다시 비활성화되며, **가장 최근 초기화 시각으로부터 24시간이 지난 후** 초기화 버튼을 다시 활성화한다. 이전 초기화가 한 번도 없으면 첫 초기화는 바로 가능하다.
- 초기화 시 직전 초기화 이후, 첫 초기화라면 개편 활성화 이후 현재 시각까지 발생한 확인된 토큰 사용량을 지갑 잔액에 한 번 적립한다. 새 행성의 주기 토큰 수와 성장 크레딧은 0부터 시작한다. 아바타와 닉네임은 유지한다.
- 지갑 잔액은 행성 초기화 사이에도 보존된다. 향후 상점에서 아이템 구매에 쓰는 재화로 사용할 수 있도록 설계하되, 상점과 구매 기능은 이번 개편 범위에 포함하지 않는다.
- 누적 토큰 사용량 점수판은 원본 사용량의 합계이므로 지갑 적립이나 향후 지출로 줄어들지 않는다. 지갑 잔액과 점수판 토큰 수는 별도 값이다.
- 초기화와 지갑 적립은 한 번만 반영되도록 동일한 원장 이벤트로 처리한다. 오프라인 중 초기화한 경우에도 로컬 상태를 보존하고 재연결 시 중복 없이 동기화한다.

## 기록 전환

행성 개편 이전의 토큰 사용 기록은 새 행성, 지갑, 점수판에 반영하지 않는다. 새 버전이 활성화될 때 기존 집계값을 성장 기준선으로 기록하고, 그 이후 새로 관측한 사용량만 개편 후 누적량으로 계산한다. 기존 원본 및 집계 기록은 삭제하지 않으며 개인 사용량 화면에서는 과거 합계를 계속 확인할 수 있다.

## 동기화와 개인정보

- Rust 수집기가 기존처럼 원본 기록을 로컬에서 읽고 중복을 제거한다. 프롬프트, 응답 텍스트, 파일 경로와 세션 식별자는 기기 밖으로 보내지 않는다.
- 기존 멤버·기기·일자별 사용량 집계 업로드와 오프라인 큐를 유지한다.
- 그룹 멤버에게 공개되는 파생 정보는 닉네임, 아바타, 시대와 행성 오브젝트, 누적 토큰 사용량, 현재 행성 성장 크레딧과 각 순위표에 필요한 값으로 한정한다.
- 서버는 인증된 같은 그룹 멤버에게만 순위표와 행성 상태를 제공한다. 원본 이벤트 키와 원본 기록은 계속 로컬에만 둔다.
- 아바타 선택, 지갑 잔액, 행성 상태는 계정의 여러 기기에서 일관되도록 버전이 있는 파생 상태로 동기화한다. 사용자 본인에게는 수집 범위와 불완전 상태를 표시한다.
- 동기화 오류가 있어도 캐시된 행성 화면은 열리며, 대기 중인 변경은 기존 큐에 보존해 재시도한다.

## 기술 경계

- 프론트엔드는 픽셀 행성 디오라마, 아바타 선택, 개인 대시보드, 동등한 행성 갤러리와 두 점수판을 렌더링한다.
- Rust 로컬 계층은 수집, 중복 제거, 성장 기준선, 크레딧 누적, 안정적인 랜덤 결과 저장, 초기화·지갑 원장과 오프라인 상태를 관리한다.
- Supabase는 기존 초대·멤버십·일일 집계를 유지하고 멤버별 행성 시각 상태, 지갑 잔액과 그룹 순위 조회 경계를 추가한다.
- 그룹 조회 RPC는 인증된 그룹 멤버만 사용할 수 있다. 순위표에 필요한 개편 후 집계만 반환하고 원본 기록이나 로컬 이벤트 키는 반환하지 않는다.
- 기존 그룹 단일 행성 요약 RPC를 멤버별 행성 상태 및 두 순위표 조회로 대체한다. 계정, 초대, 탈퇴, 동기화 중지와 집계 삭제 경로는 유지한다.

## 검증 기준

1. 첫 실행에서 남성 또는 여성 아바타와 닉네임을 설정할 수 있고, 아바타는 성장 결과에 영향을 주지 않는다.
2. 시대별 허용 오브젝트만 생성되고, 이후 시대에 갈수록 같은 성장 크레딧에서 생성되는 오브젝트 수가 감소한다.
3. 사용 기록을 재수집하거나 앱을 재시작해도 기존 생성물과 위치가 유지되고 중복 생성되지 않는다.
4. 100 크레딧에서 첨단·우주 문명이 열리며, 그 이후에도 최종 시대의 점수와 오브젝트가 계속 쌓인다.
5. 어느 시대에서든 초기화할 수 있다. 초기화 때 이번 주기의 토큰 수가 지갑에 한 번만 적립되고 새 행성은 0부터 시작한다. 이후 초기화 버튼은 마지막 초기화 24시간 뒤에 활성화된다.
6. 그룹 멤버 수만큼 독립 행성이 보이며, 토큰 사용량과 문명 발전 점수 순위표에 정확한 값과 순위가 표시된다.
7. 개편 이전 사용량은 개인 통계에 남고 새 행성, 지갑, 점수판에 들어가지 않는다.
8. 다른 참여자는 프롬프트, 응답 내용, 파일 경로와 원본 세션 기록을 볼 수 없다.
9. 오프라인으로 생성한 행성 요소와 초기화·지갑 변경은 재시작 후에도 남고, 재연결 시 중복 없이 동기화된다.

- 공개 그룹 검색, 친구 찾기, 채팅
- 남성/여성 캐릭터 간 능력·성장 차이
- 자동 생성형 행성 그림 및 사용자 작성 프롬프트 업로드
