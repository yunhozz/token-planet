# Token Planet 행성 성장 일지 설계

**작성일:** 2026-09-28
**상태:** 사용자 문서 검토 대기

## 목표와 범위

사용자가 자신의 행성이 날짜별로 얼마나 성장했는지, 시대가 언제 바뀌었는지, 초기화 때 얼마가 지갑에 적립됐는지 확인할 수 있게 한다. 일지는 여러 기기에서 같은 계정으로 수집한 사용량을 합산하고, 초기화 전후의 모든 행성 주기를 탐색할 수 있어야 한다.

이번 기능은 기존 Codex·Claude Code 수집, 성장 공식, 행성 초기화 규칙을 변경하지 않는다. 원본 대화, 프롬프트, 응답, 로컬 파일 경로, 세션 식별자와 이벤트 중복 제거 키는 서버에 보내지 않는다. 다른 그룹 멤버에게 일지의 날짜별 기록을 공개하지 않는다.

## 사용자 경험

- 상세 화면에 **성장 일지** 진입점을 둔다. 기본 조회 범위는 **최근 7일**이다. 이전 날짜는 7일 단위로 탐색한다. 초기화 이전 주기를 선택하면 그 주기의 마지막 날짜가 포함된 7일 화면에서 시작한다.
- 기록이 확인된 날짜에 확인 토큰 합계, 성장 크레딧, Codex·Claude Code별 수집 상태를 표시한다. 한 날짜에 초기화가 있으면 초기화 전후를 서로 다른 주기 항목으로 보여준다.
- 성장 크레딧 누적이 `5·20·50·100`을 처음 넘은 날짜에 시대 도달 표시를 둔다. 날짜만 확인할 수 있는 집계에서 정확한 시각을 추정하지 않는다. 과거 기록이 수정돼 도달 날짜가 바뀌면 현재 확인된 집계를 기준으로 다시 계산한다.
- 초기화 항목에는 초기화 시각과 해당 주기에서 지갑에 한 번 적립된 토큰을 표시한다. 현재 주기는 진행 중으로 표시한다.
- 기록이 없는 날짜는 0 토큰으로 채우지 않는다. 명시적으로 확인된 0과 미확인 값은 다르게 취급한다. 새 기능 이전의 다른 기기 기록이 없는 과거 구간에 대해서는 별도 불완전 안내나 배너를 추가하지 않는다.
- 로그인하지 않은 상태에는 이 기기에 저장된 기록만 보여준다. 로그인 상태에는 마지막으로 동기화된 계정 전체 기록과 이 기기의 미전송 변경을 기기 ID별로 합쳐 보여준다. 같은 기기의 서버 기록과 로컬 기록을 중복 합산하지 않는다. 기존 동기화 상태 표시는 그대로 이용한다.
- 행성 개편 활성화 이전의 사용량은 기존 개인 전체 사용량 화면에 남기고 성장 일지에는 넣지 않는다.

## 기록 모델과 계산

기존 로컬 `usage_record`와 `planet_usage_owner`를 계정 소유·중복 제거의 기준으로 사용한다. 로컬 계층은 기록 시각과 행성 주기 경계로 사용량을 나눈 뒤, 기기·주기·날짜·에이전트별 **절대 일일 집계**를 만든다. 날짜는 해당 계정 행성의 고정 IANA 시간대를 따른다. 초기화가 하루 중간에 일어나면 같은 날짜가 두 주기에 각각 속할 수 있다.

서버에는 계정 전용 주기 경계와 일별 집계를 보관한다. 일별 키는 계정, 기기, 주기, 날짜, 에이전트로 구성하고, 확인 토큰과 수집 상태, 단조 증가 수정 번호와 멱등 해시만 저장한다. 재수집·파일 재검사로 과거 수치가 늘거나 줄면 같은 키의 최신 절대값으로 교체한다. 수집원을 사용 안 함으로 바꾼 경우에도 영향을 받는 날짜를 다시 집계해 이전 값이 남지 않게 한다. 초기화 경계는 기존 지갑 적립 기록과 일치하는 주기 ID·시작·종료 시각으로 보관하며, 동일한 초기화를 여러 기기가 재전송해도 한 번만 반영한다. 오래된 주기의 집계는 이후 초기화로 지우지 않는다.

계정의 한 주기·하루에 속하는 모든 기기와 활성화된 에이전트의 **확인 토큰을 먼저 합친 후** 기존 공식 `log2(1 + 토큰 / 100,000)`을 한 번 적용한다. 주기 성장 크레딧은 그 주기의 일별 크레딧 합계다. 소스의 불완전한 사용량은 확인된 부분만 합산하고 `null`을 0으로 바꾸지 않는다. 서버는 인증된 본인만 호출할 수 있는 쓰기·읽기 API로 주기와 일별 기록을 다룬다. 그룹 행성·순위 조회 API의 응답에는 이 상세 기록을 추가하지 않는다.

일지의 첫 동기화 때 현재 기기에 남은 계정 소유 기록과 주기 경계 중 안전하게 귀속할 수 있는 날짜를 소급 집계한다. 다른 기기에서 과거 기록이 아직 업로드되지 않았거나 기기가 사라졌다면 그 기록은 추정하거나 기존 그룹 집계에서 복원하지 않는다. 과거 그룹 집계는 세계 시간대와 삭제 정책이 다를 수 있기 때문이다. 과거 데이터가 없는 날짜는 일지에 나타나지 않는다.

## 동기화와 삭제

- 일지 업로드는 기존 계정 동기화 경로와 오프라인 대기열을 사용한다. 계정 전환 시 대기열과 캐시를 계정별로 분리한다. 네트워크 재시도·앱 재시작 후에도 같은 절대 집계가 중복 증가하지 않는다.
- 동기화 일시정지는 일지 업로드도 멈춘다. 그룹을 탈퇴해도 계정 전용 일지는 보존한다. **공유된 내 집계 삭제**는 그룹 집계만 삭제하며 개인 일지에는 영향을 주지 않는다.
- 별도의 **개인 일지 삭제** 동작은 계정에 저장된 일별·주기 기록을 지우고, 서버에 삭제 시각과 세대를 보존해 다른 기기의 오래된 대기 항목이 복원하지 못하게 한다. 각 기기는 다음 동기화 때 이 삭제 상태를 받아 적용한다. 원본 에이전트 로그와 기존 행성·지갑 상태는 삭제하지 않는다. 기존 행성 주기 ID는 유지하되 일지에는 삭제 시각 이후에 발생한 기록만 다시 싣는다. 화면에도 사용자가 직접 삭제한 시점 이후의 일지만 보인다.
- 계정 삭제 시에는 개인 일지 집계와 삭제 상태도 함께 삭제한다. 일지 조회·삭제 권한은 본인 계정에만 부여한다.

## 기술 변경 범위

| 영역 | 변경 |
| --- | --- |
| React | 상세 화면의 성장 일지, 7일 단위 탐색, 주기 선택, 날짜별 상태와 초기화 항목 |
| Rust·SQLite | 계정별 주기 경계·일별 집계 읽기 모델, 수정 번호와 대기열, 서버 캐시·로컬 변경 병합, 삭제 시각 적용 |
| Supabase | 본인 전용 일별·주기 기록과 삭제 정책, 멱등 업로드·조회·삭제 API, 계정 격리 정책 |

기존 `planet_object`에는 생성 시각이 없고 초기화 때 현재 장면의 오브젝트만 남으므로, 이번 일지에 과거 오브젝트의 정확한 생성 시각이나 과거 행성 장면 재현은 포함하지 않는다. 상점·구매, 그룹 공동 목표, 새로운 수집원도 범위 밖이다.

## 검증 기준

1. 기본 화면은 최근 7일이며 이전 주기와 이전 날짜를 탐색할 수 있다. 빈 날짜를 0으로 채우지 않는다.
2. 두 기기의 같은 주기·하루 사용량은 합산한 뒤 성장 공식을 한 번 적용한다. 같은 기기의 로컬 대기분과 서버 값을 이중 계산하지 않는다.
3. 하루 중 초기화하면 전후 기록이 다른 주기로 나뉘고, 지갑 적립 항목은 기존 원장 값과 일치한다.
4. 과거 사용량 정정·재검사·재시도 후 일별 수치와 시대 도달 날짜가 최신 확인 기록과 일치한다. 원본 사용량을 중복 업로드하지 않는다.
5. 동기화 일시정지와 오프라인 재시작 동안 대기분이 보존되고, 계정 전환 후 다른 계정 일지가 보이지 않는다.
6. 그룹 집계 삭제·탈퇴는 개인 일지를 지우지 않는다. 개인 일지 삭제 뒤 다른 기기의 오래된 대기분이 삭제한 과거를 복원하지 않는다.
7. 본인 외의 계정과 그룹 멤버는 날짜별 일지를 읽을 수 없다. 서버 요청과 응답에 원본 기록·경로·프롬프트·세션 ID가 없다.

## 출시 의존성

개인 일지의 계정 전체 합계는 호스팅 Supabase 마이그레이션과 인증이 동작해야 검증할 수 있다. 현재 저장소의 출시 점검 문서에는 호스팅 OTP와 macOS·Windows 실기 확인이 남아 있다. 이 기능을 출시했다고 판단하기 전에 최신 개인 행성 마이그레이션을 포함한 서버 상태와 두 기기 간 일지 동기화를 직접 확인한다.
