# 행성 상점 구매 후 배치 UX 설계

**상태:** 사용자 승인 완료 (2026-10-07)

## 목표

상점에서 행성 장식을 구매한 뒤 무엇을 샀는지 알아보고, 원하는 위치에 쉽게 배치하고, 이미 놓은 장식은 자연스러운 화면 조작으로 보관함에 되돌릴 수 있게 한다.

## 확인된 문제

- 구매 성공 안내가 일반 문구라 상품명을 확인하기 어렵다.
- 풍경의 선택 UI는 장식 이름과 기본 `보관` 버튼만 보여 화면 테마와 어울리지 않는다.
- 배치 포인터 입력은 이동 거리가 4px 이상이어야 저장을 시도하므로 빈 위치를 한 번 클릭하는 동작은 배치되지 않는다.
- 배치할 수 없는 위치와 제한 이유가 충분히 드러나지 않는다.

## 결정된 설계

1. **구매 결과:** 조경 상품 구매가 성공하면 상품명과 실제 변형 썸네일을 보여 주고 `행성에 배치하기`와 `계속 쇼핑`을 제공한다. 버튼은 구매 응답 상태에서 새로 추가된 동일 SKU 인스턴스가 유일하게 식별될 때만 그 `instance_id`를 선택한다. 후보가 없거나 여러 개면 임의 선택하지 않고 구매 안내와 보유함 경로를 보여준다. 불확실한 요청 재시도는 최초 구매 전의 ID 기준을 유지한다. 기존 요청/응답 계약은 변경하지 않는다.
2. **풍경 선택 카드:** 풍경 테마의 바탕, 테두리, 여백을 사용하는 하단 카드로 교체한다. 미배치 장식에는 썸네일, 이름, `배치 중`, 위치 안내, `배치 확정`, `취소`를 제공한다. 배치된 장식에는 썸네일, 이름, `배치됨`, `위치 이동`, `보관함으로`, 선택 닫기를 제공한다. 썸네일은 기존 `ShopProductThumbnail`을 재사용한다.
3. **위치 선택:** 배치 중인 장식의 유효한 미리보기를 풍경 중심 부근에서 시작한다. 풍경 클릭 또는 드래그로 draft 위치를 정하며, `배치 확정` 또는 Enter만 저장 요청을 보낸다. Esc 또는 `취소`는 저장하지 않고 종료한다. 유효하지 않은 위치에서도 draft를 유지해 위치를 다시 고를 수 있으며, 불가 사유를 표시한다. 기존에 배치된 장식의 이동도 같은 draft 후 확정 흐름을 따른다.
4. **상태 안전:** 기존 계정, 주기, 인스턴스 버전, 중복 요청 및 불확실 결과 가드를 유지한다. 계정/주기가 바뀌면 이전 선택과 draft를 초기화한다. 좁은 창에서 카드가 줄바꿈되고 풍경 조작을 가리지 않게 한다.

## 수용 기준

1. 조경 상품 구매 성공 후 상품명과 실제 변형 썸네일이 보인다. `행성에 배치하기`는 유일하게 식별된 새 인스턴스를 선택하고, 식별이 모호하면 임의의 인스턴스를 선택하지 않는다.
2. 선택된 미배치 상품은 풍경 카드에서 썸네일, 이름, 배치 상태와 위치 선택 안내를 확인할 수 있다.
3. 클릭 또는 드래그로 위치 draft를 정할 수 있으며, 확대/축소 상태에서도 미리보기와 저장 좌표가 일치한다.
4. 유효하지 않은 위치와 그 이유가 보이고, 해당 draft는 성공으로 처리되거나 사라지지 않는다.
5. 확정 또는 Enter는 배치 요청을 한 번만 보내며, 취소 또는 Esc는 저장 요청 없이 draft를 종료한다.
6. 요청 중 중복 입력은 차단된다. 성공, 실패, 불확실 결과가 각각 올바른 상태 안내를 남긴다.
7. 계정/주기 변경 또는 인스턴스 버전 충돌 때 오래된 선택과 draft를 제출하지 않는다.
8. 배치된 장식의 `보관함으로`는 기존 retrieve 동작을 호출하고, 결과 상태를 표시한다.
9. 카드의 버튼과 텍스트는 기존 행성 화면 테마에 맞고 좁은 창에서 줄바꿈되며 풍경 조작을 막지 않는다.

## 범위 밖

- 구매 API나 `ShopActionResult` 계약의 서버 변경
- 구매 직후 자동 배치 또는 구매 즉시 화면 전환
- 기존 상품 가격, 소유 제한, 배치 규칙 변경

## 주요 위험과 처리

`ShopActionResult`는 새 인스턴스 ID를 별도 영수증으로 반환하지 않는다. 따라서 요청 전 보유 ID와 성공 응답의 동일 SKU 인스턴스를 비교하되, 정확히 하나의 새 후보가 확인되는 경우에만 연결한다. 불확실 재시도에서도 같은 기준을 사용한다. 0개 또는 복수 후보는 자동 연결을 중단하고 보유함에서 직접 선택하도록 안내한다. 이 한계는 응답 계약을 바꾸지 않는 범위에서 임의 선택을 방지한다.
