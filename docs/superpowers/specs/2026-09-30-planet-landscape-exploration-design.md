# 행성 상세 풍경·탐사 및 앱 내부 화면 전환 설계

작성일: 2026-09-30

## 목적과 승인된 방향

현재 내 행성 자세히 보기는 홈과 같은 원형 행성을 크게 보여준다. 사용자는 자세히 보기에서 평평한 대지와 풍성한 풍경을 보고, 오브젝트를 더 크게 구별하고 탐사하고 싶어 한다. 또한 행성 꾸미기와 성장 일지를 별도 창 대신 현재 앱 안에서 열기를 요청했다.

대화에서 다음 두 설계 섹션을 승인받았다.

1. 상세 보기 전용 평면 풍경과 확대·이동·오브젝트 선택·목록 탐사.
2. 상점과 성장 일지의 앱 내부 화면 전환, 복귀 상태 보존, 계정 및 행성 컨텍스트 보호.

구현 순서는 평면 풍경을 먼저 만들고, 탐사 조작을 연결한 뒤 앱 내부 화면 전환을 완성한다. 이 문서는 구현 전 사용자 검토 대상이다.

## 범위와 제약

- 기존 픽셀 아트, 어두운 배경, 민트·금색 중심의 시각 언어를 따른다.
- 홈과 그룹 카드의 원형 `PlanetScene`을 유지하고 내 행성 상세 화면에 별도 평면 풍경 컴포넌트를 사용한다.
- 저장된 성장 오브젝트, 성장 점수, 시대, 토큰, 장식 구매·장착 데이터 모델을 변경하지 않는다.
- 평면 풍경의 풀·지면 무늬 등 장식은 화면 표현용이다. 성장 오브젝트 수, 생성 기록, 토큰에 합산하지 않는다.
- 별도 렌더링 엔진이나 라우팅 라이브러리 없이 기존 React·SVG 구조를 확장한다.
- 사용자가 수정한 `docs/superpowers/.DS_Store`는 이번 변경에 포함하지 않는다.

## 풍경과 데이터 배치

상세 화면의 풍경은 좌우를 꽉 채우는 평면 장면으로 표현한다. 앱 상세 화면에서 사용할 수 있는 콘텐츠 영역의 왼쪽 끝부터 오른쪽 끝까지 이어지게 하고, 풍경 구간에는 일반 카드의 안쪽 여백·테두리·최대 너비 제한을 적용하지 않는다. 창 크기에 따라 장면의 표시 너비와 높이를 조정하며 별도의 사각 액자 안에 넣지 않는다. 원형 마스크를 사용하지 않고 수평 지면 위에 시대에 맞는 길·수목·물·건물과 지면 장식을 배치한다. 현재 시대와 행성 요약·기록·도구는 풍경 아래에 배치해 풍경의 너비를 줄이지 않는다. 좁은 화면에서도 풍경은 좌우 전체 너비를 사용하고, 조작부와 선택 카드·목록은 줄바꿈하거나 풍경 아래로 배치해 모든 기능에 접근할 수 있게 한다. 풍경 내부의 카메라 이동이 페이지 전체의 가로 넘침을 만들지 않게 한다.

실제 오브젝트는 `PlanetObject`의 `stage`, `ordinal`, `kind`, `x`, `y`, `seed`를 입력으로 사용한다. 식별자는 기존의 `stage-ordinal`을 사용한다. 좌표와 seed를 활용한 결정적 배치를 통해 같은 행성의 새로고침과 화면 복귀에서 오브젝트 위치가 바뀌지 않게 한다. 겹치는 오브젝트는 안정적인 순서로 펼치고 전경·후경 깊이에 따라 그려 선택 가능한 표시 영역을 확보한다. 오브젝트가 많으면 풍경의 탐사 가능한 영역을 확장하며 저장 데이터를 다시 쓰지 않는다.

상세 풍경에서는 타일당 마지막 네 개만 보여주던 제한과 `+N` 묶음을 제거한다. 저장된 모든 실제 오브젝트에 개별 표시 위치와 목록 항목을 제공한다. 전체 보기에서는 모든 오브젝트를 포함한 풍경 범위를 맞추고, 개별 선택 시에는 해당 오브젝트를 구별할 수 있는 확대 수준으로 이동한다. 빈 행성도 지면과 자연 장식을 갖춘 풍경으로 보여주되 실제 오브젝트가 없다는 안내를 표시한다.

아바타는 지면 위에서 보인다. SVG 고유 크기를 유지해 풍경 확대에 따라 의도된 크기로 렌더링한다. 기존 장착 장식은 평면 풍경에서도 확인 가능해야 한다. 지면·앞마당 장식은 대지에, 하늘 장식은 하늘에, 고리 계열은 하늘의 행성 상징에 표현해 장착 결과를 식별할 수 있게 한다.

## 탐사 조작과 선택

풍경에는 확대·축소·전체 보기 버튼을 둔다. 확대 상태에서 드래그로 이동하고 방향키 조작도 제공한다. 카메라는 풍경의 유효 범위 안으로 제한하고 창 크기가 바뀔 때 범위에 맞게 보정한다. 전체 보기는 선택 여부와 관계없이 풍경 전체를 다시 보여준다.

실제 오브젝트를 클릭하거나 목록에서 선택하면 같은 선택 상태를 갱신하고 카메라를 해당 위치로 이동한다. 선택한 오브젝트는 풍경에서 강조하고 카드에 다음 정보를 표시한다.

- 오브젝트 이름: 기존 `objectName` 매핑 사용.
- 생성 시대: 기존 `STAGE_NAMES` 매핑 사용.
- 해당 시대의 생성 순서: `ordinal`의 도메인 순서를 사용자에게 표시.

현재 모델에는 생성 날짜가 없으므로 날짜를 추정하거나 표시하지 않는다. 장식용 풍경 요소를 실제 성장 오브젝트의 목록이나 카드에 포함하지 않는다. 목록은 모든 실제 오브젝트를 포함하고 키보드로 선택할 수 있다. 빈 목록에는 아직 생성된 오브젝트가 없다는 안내를 둔다.

선택 대상이 데이터 갱신 뒤 사라지면 선택을 해제한다. 계정 또는 행성 컨텍스트가 바뀌면 카메라와 선택을 초기화한다. 일반적인 같은 행성의 갱신에서는 현재 선택이 유효한 한 유지한다. 동작 감소 설정에서는 카메라 이동 효과를 즉시 적용한다.

## 컴포넌트와 상태 책임

- 기존 `PlanetScene`: 홈·그룹의 원형 행성 표현을 담당한다.
- 상세 풍경 컴포넌트: 배치된 오브젝트·장착 장식·아바타를 SVG로 그리고 탐사 조작과 선택 정보를 보여준다.
- 풍경 배치 모듈: 저장 오브젝트에서 결정적인 표시 위치와 풍경 경계를 계산한다. 실제 성장 데이터를 수정하지 않는다.
- `App`: 현재 내부 화면과 계정/행성 컨텍스트, 서버 데이터, 탐사 카메라·선택 상태의 수명을 관리한다.
- 기존 `CosmeticShop`과 `GrowthJournal`: 구매·장착·기록·삭제 인터페이스를 재사용한다.

탐사 상태는 화면 전환으로 풍경 컴포넌트가 사라져도 유지되는 상위 상태에 둔다. 동일 계정·행성에서 상점이나 일지를 다녀오면 카메라 위치·확대 수준·선택 오브젝트를 복원한다. 각 렌더러와 조작부는 동일한 배치 결과를 사용해 표시 위치와 선택 위치가 어긋나지 않게 한다.

## 앱 내부 화면 전환

내부 화면은 내 행성, 행성 꾸미기, 성장 일지로 구분한다. 상세 보기에서 상점·일지 버튼을 누르면 현재 창의 콘텐츠를 전환하고 상세 창 크기를 유지한다. 이 버튼 경로에서는 `WebviewWindow` 생성이나 `window.open`을 호출하지 않는다.

상점에는 기존 상품 UI와 행성 미리보기를 표시한다. 성장 일지에는 기존 기록 UI를 표시한다. 두 화면에 `내 행성으로 돌아가기`를 두고 복귀하면 이전 탐사 상태로 내 행성을 보여준다. 화면 전환 뒤에는 목적지 제목 또는 주요 조작부로 키보드 포커스를 옮긴다. 기존 홈으로 돌아가기와 내 행성/그룹 탭 전환은 계속 사용할 수 있다.

장착되지 않은 상점 미리보기는 상점을 나갈 때 해제한다. 구매·장착이 완료된 결과는 앱의 확정된 상점 상태를 갱신해 복귀 풍경과 홈 행성에 반영한다. 구매만 한 상품을 자동 장착하지 않는다.

기존 별도 창용 URL을 읽는 코드와 내부 화면 상태를 구분한다. 구현 시 별도 창 생성 경로를 정리하되 계정 전환 및 장식 갱신 이벤트의 발신자 식별자는 현재 앱의 실제 창인 `main`과 일치하도록 유지한다. 내부 화면 이름을 창 발신자 ID로 사용하지 않는다. 오래된 별도 창 URL이 직접 열리는 경우에도 새 내부 화면 렌더링과 데이터 보호를 사용한다.

## 계정·행성 컨텍스트와 실패 처리

현재 `App`의 상점 컨텍스트, 요청 generation, world transition epoch, 일지 요청 ID 및 소유자 검사를 보존한다. 계정이나 행성 컨텍스트가 잠긴 동안 구매·장착·기록 삭제를 차단하고 확인 중 상태를 표시한다.

계정, 공동 세계 컨텍스트 또는 행성 사이클이 바뀌면 이전 탐사 상태·선택·임시 장식 미리보기와 캐시를 무효화한다. 늦게 도착한 이전 컨텍스트의 응답을 현재 화면에 반영하지 않는다. 현재 내부 화면은 유지하면서 그 화면에 필요한 현재 컨텍스트 데이터를 다시 읽는다. 프로필 설정이나 초기 사용량 로딩은 기존 앱 진입 흐름을 따른다.

상점 진입 시 현재 컨텍스트의 상점 상태를 불러오고, 일지 진입 시 현재 계정의 기록을 불러온다. 기존 새로고침, 구매 실패, 장착 실패, 일지 불러오기 실패와 재시도, 삭제 권한 및 삭제 처리 UI를 유지한다. 화면을 떠난 후 도착한 유효 응답은 컨텍스트가 같은 경우만 저장하고 다른 화면의 오류 알림으로 노출하지 않는다. 다시 진입하면 해당 화면에서 최신 상태와 오류를 확인할 수 있다.

## 수락 기준과 검증

1. 홈의 원형 행성과 내 행성 상세의 평면 풍경이 명확히 구별되고 기존 픽셀 스타일을 따른다. 상세 풍경은 창 크기에 맞춰 콘텐츠 영역의 좌우 끝까지 채우며 카드 안쪽 여백·테두리·최대 너비 제한으로 축소되지 않는다.
2. 빈 행성, 여러 시대, 겹친 좌표, 다수 오브젝트에서 풍경 배치가 안정적이며 모든 저장 오브젝트가 개별 표시와 목록 탐사 대상이 된다. `+N` 축약이 없다.
3. 확대·축소·전체 보기·이동·직접 선택·목록 선택이 작동하고 선택 카드는 이름·시대·순서를 정확히 표시한다.
4. 화면 너비가 바뀌어도 풍경 조작과 목록에 접근할 수 있고 키보드 조작과 동작 감소 설정을 지원한다.
5. 상점과 일지 버튼은 같은 창에서 화면을 전환하고 새 Tauri 창이나 브라우저 팝업을 만들지 않는다.
6. 상점/일지 복귀 시 같은 계정·행성의 탐사 상태를 복원하고 임시 미리보기는 해제한다. 확정된 장착은 상세 풍경과 홈에 반영된다.
7. 계정·공동 세계·행성 사이클 변경 후 이전 응답과 선택이 현재 컨텍스트에 섞이지 않는다. 기존 구매·장착 및 일지 권한·로딩·실패·재시도·삭제 동작을 보존한다.
8. 성장 오브젝트 수와 성장 수치가 풍경 장식으로 변경되지 않는다.

검증은 기존 자동 검사와 변경에 필요한 동작 검사를 사용하며 실제 풍경의 시각 확인도 수행한다. 브라우저에서 확인한 동작과 Tauri에서 확인한 창 동작을 구별해 보고한다. 수행하지 않은 환경의 검증을 통과했다고 주장하지 않는다. 구현 계획에서 구체적 검사 명령과 담당 파일을 확정한다.

## 현재 구현 근거

- `apps/desktop/src/components/PlanetScene.tsx`: 원형 SVG, 타일당 마지막 네 개 표시와 `+N` 축약, 오브젝트 이름·시대 매핑.
- `apps/desktop/src/App.tsx`: 홈/상세의 `PlanetScene` 사용, 기존 상점·일지 JSX와 데이터 보호, `launchFeatureWindow` 및 `changeView`.
- `apps/desktop/src/lib/featureWindows.ts`: Tauri `WebviewWindow`와 브라우저 `window.open` 생성.
- `apps/desktop/src/types/usage.ts`: `PlanetObject` 저장 필드. 날짜 필드 없음.
- `apps/desktop/src/App.css`: 기존 픽셀 스타일과 상세/상점/일지 배치.

## 문서 자체 검토

작성 후 placeholder, 내부 모순, 해석이 달라질 수 있는 요구사항, 범위를 검토했다. 실제 오브젝트와 장식의 구분, 날짜 미표시, 장착과 미리보기의 차이, 화면 상태와 창 발신자의 구분, 컨텍스트 변경 시 탐사 상태 초기화와 일반 복귀 시 복원을 명시했다. 사용자 검토에 따라 풍경이 좌우 전체 너비를 사용하도록 수정하고, 프레임 없이 표시할 영역과 좁은 화면의 조작부 배치를 명시했다. 요약을 아래에 두어 풍경 너비 요구사항과 충돌하지 않게 했다. 구현 범위는 위 세 사용자 요청과 이를 안전하게 연결하는 상태 관리로 제한했다.
